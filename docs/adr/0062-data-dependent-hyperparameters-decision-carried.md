# Data-dependent imputation hyperparameters are decision-carried, resolved from the profile

ADR-0060 made the `ImputationDecision` a pure function of `(profile, shape, config)` and pulled `model_choice` to decide-time so the plan is a complete, inspectable, overridable artifact. This ADR settles the remaining fit-time array reads in `_numeric_imputer.py` — the model *hyperparameters* (`max_iter`, `tol`, `n_neighbors`, `weights`, `initial_strategy`, `n_nearest_features`) and the KNN scaling params — classifying each as either **decision-carried** (resolved in the decision layer from profile statistics) or **execution-computed** (a learned value the plan cannot hold). The outcome: with one new profiler metric, **every hyperparameter becomes decision-carried**, and execution computes only genuinely-learned values.

Locked decisions:

- **Hyperparameters are plan parameters, not execution detail.** `max_iter`/`tol`/`n_neighbors` are *dials* (choices about how to run the machine), not values learned from data, so — by the same reasoning ADR-0060 applied to `model_choice` — they belong on the plan where a user can inspect and override them per-unit. This extends full-configurability (the standing "advanced-developer library" stance) from global config knobs to per-unit plan edits.
- **The cleanly profile-sourced dials move to the decision layer as-is.** MICE `tol` / Regression `tol` (from `IQR` + `NonlinearityTag`), MICE `initial_strategy` (skewness severity), MICE `n_nearest_features` (pairwise Pearson), KNN `weights` (block miss-fraction + feature count), and the block miss-fraction / n-missing-feature-count they depend on (the mean/count of per-column `effective_null_ratio` — additive, so exactly reconstructible from marginals).
- **A missing profile stat degrades to a neutral default, never an array fallback.** Today several functions re-compute from the raw array when a stat (`feature_correlation`, `iqr`, `r2_gap`) is absent; the pure decision layer has no array, so absence falls back to the existing hard-coded default (`tol → 1e-3`, correlation signal contributes nothing). A thin profile yields a slightly more conservative plan rather than a data peek — and a plan that still exists rather than one that refuses to build.
- **Complete-row fraction is the single genuinely-joint signal, resolved by a new profiler metric.** The share of rows with no missing across a column set is *non-additive* — it cannot be rebuilt from per-column null ratios (aligned vs scattered holes give the same marginals, different completeness) — and it is subset-specific. Rather than split the dial into execution or drop the signal, the missingness profiler exposes it. It is nearly free: the profiler already computes the per-row missing-count vector (for `row_missingness_p90`) and discards all but that percentile; we harvest one more scalar from the same vector.
- **The metric is one dataset-level float: `complete_row_fraction` on `RowMissingnessDistribution`.** `(row_missing == 0).mean()` over all analysed columns, surfaced at `profile.dataset.row_distribution`. Not the full histogram (no consumer beyond the three dials, which only test coarse `<0.2`/`<0.5` bands) and not any per-subset structure (exact per-subset completeness would require storing the missing-indicator matrix — raw data, forbidden by ADR-0060).
- **KNN scaling params are learned fitted-state, not dials — execution-only.** `col_means`/`col_stds` are `nanmean`/`nanstd` of `train_df`: learned values in the same class as fill values and fitted coefficients, which ADR-0060 bars from the value-free plan. They stay inside `_FittedKNN`/`FittedUnit`; the plan carries nothing about them (the *policy* that KNN standardizes is implied by the strategy choice).
- **All dials attach to `ImputationUnit`, resolved by the assembler at build.** Block dials (MICE/KNN) have no per-column home, so for one uniform rule every dial hangs on the unit — the training atom execution fits and #337 checkpoints. The assembler resolves them in the same pass that resolves `model_choice`. Per-unit override follows the immutable `with_...` pattern (`with_unit_hyperparameters(unit_id, ...)` → new plan); the exact API is left to the object-shape (#334) / serialization (#337) tickets.

## Status

accepted

## Considered Options

- **Split the mixed dials into execution** — decision carries a `max_iter` from the profile signals, execution applies the complete-row-fraction nudge from the real array at fit time. Rejected: the number on the plan would no longer be the number that runs, walking back ADR-0060's "the plan carries the final, overridable recipe" for this one signal, and forcing #337 to choose pre- vs post-nudge storage.
- **Drop the complete-row-fraction signal entirely.** Rejected: it is a real convergence signal, and discarding it purely for architectural tidiness violates the "compute all available indicators / accuracy over speed" principle.
- **Carry per-subset completeness in the plan** (store the missing-indicator matrix so any block's exact completeness is reconstructible). Rejected on sight: that is raw data in an object ADR-0060 defined as value-free.
- **Make the profiler stats mandatory** (hard-error when `feature_correlation`/`iqr` is absent) instead of neutral defaults. Rejected: legitimately-absent stats (a constant column has no IQR, a single-column frame has no correlations) would make the plan un-buildable; graceful degradation is the honest default.

## Consequences

- The missingness profiler gains one field (`RowMissingnessDistribution.complete_row_fraction`); the decision assembler reads it for the three convergence dials. The dataset-wide fraction underestimates any single block's completeness, so `max_iter`/`n_neighbors` nudge slightly **up** relative to today's exact per-block computation — the safe direction (more convergence, not less).
- The six hyperparameter functions in `_numeric_imputer.py` move from fit-time (array-fed) to decide-time (profile-fed); the array-fallback branches inside them are deleted in favour of neutral defaults.
- `_FittedKNN`'s scaling params are unaffected — they were already execution fitted-state; this ADR only confirms they never migrate to the plan.
- #337 (serialization/versioning) now knows the full set of decision-carried fields includes per-unit hyperparameters; nothing execution-computed except learned artifacts crosses the persistence boundary.
