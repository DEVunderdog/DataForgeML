# Agents reach the library through a CLI and a Skill

ADR-0099 chose two deliveries for the Operations, Code Mode and Tool Calls, and said there is no library CLI. Two findings changed that. First, we will not build a Harness, so the library has to work in the Harnesses Agents already use: Claude Code, Codex, Gemini CLI, Cursor. Second, the [Harness research](../research/harness-capabilities-vs-contract.md) found that those Harnesses read MCP `tools/list`, not our catalogue. They drop `input_examples`. They cut tool descriptions. And in their shells the Agent can set any env var. Every one of them gives the Agent a shell, though, and Agents are good at shells. `playwright-cli` shows the pattern: one CLI that wraps the whole library, plus a Skill that teaches it. This ADR moves DataForgeML to that pattern. The Operations, Wire Records, Library Errors, Handles, Dataset Digest, Routing Reason, Dial Pointers, Literal Fields and `query_frame` are unchanged. Only the delivery around them changes.

## Status

accepted. Decided on 2026-10-11 in a grilling session against [Spec: Agent-native DataForgeML](https://github.com/DEVunderdog/DataForgeML/issues/588) and [Map: an agent-native DataForgeML](https://github.com/DEVunderdog/DataForgeML/issues/568), without a new map, because the session settled every open question. It amends ADR-0099, 0100, 0101, 0102, 0103, 0104, 0107, 0108, 0110 and 0111, and supersedes ADR-0109. Planning only: no code changes yet.

## Decisions

- **The CLI is the primary delivery, and Code Mode is the second.** `dataforge <command>` runs one Operation. The Skill teaches the CLI. Operations stay importable from Python (Code Mode), because the CLI is generated from the same function and costs nothing extra. Gained: one delivery that works in every Harness with a shell, and Python glue where an Agent wants it. Given up: Harnesses with no shell (API-only apps, chat clients) get nothing, until MCP returns as a generated add-on from the same source.
- **Tool Calls, the `[mcp]` extra and the Operation Catalogue are deleted.** ADR-0109 is superseded. The facts the catalogue held for the Harness either move to `--help` (whether a command scales with data, its Error Codes, its See Also) or go (effect hints, `load_first`, `definition_tokens`, `_meta`). Gained: no `_meta` prefix problem, no `input_examples` field that no Harness reads, and one less generated file. Given up: a Harness cannot register DataForgeML as typed tools without writing its own adapter.
- **A CLI command is the shell spelling of an Operation, not a new concept.** Command names are the Operation names in kebab-case (`describe_columns` → `describe-columns`). Flags are the parameter names in kebab-case. Gained: one concept and one name, so docs never say "command X maps to Operation Y". Given up: one spelling rule to remember.
- **The Harness contract shrinks.** The Harness provides a shell with Python ≥ 3.11, the library installed with `dataforge` on the PATH, and the Skill installed. Resource limits stay the Harness's. Gained: any off-the-shelf Harness qualifies without extra setup. Given up: the library no longer assumes a sandbox, no network, or read-only mounts.
- **Workspace Settings are user-set guardrails, not a boundary.** The Workspace, the Literal Policy, the Declared Inputs and the core budget are set in `.dataforge/config.toml`. A flag beats an env var, which beats the config file, which beats the default. In a shell the Agent types the flags and can change any of these, so the library does not claim to enforce them. Real enforcement is the Harness's own permission rules: limiting the Agent to `Bash(dataforge:*)`, and deny rules on reading the raw CSV. The docs say this plainly. Gained: the guardrails still work for well-behaved Agents and for Harnesses that restrict the shell, and the contract stops claiming something no measured Harness provides. Given up: any claim that the library itself is a security boundary. A user-started daemon holding the settings was rejected, because the Agent could start its own.
- **Each command is one short-lived process. The Workspace is the session.** The Workspace is `.dataforge/` in the working directory by default, or `--workspace`. Write-once, multi-process Handles (ADR-0103) need no change. Gained: no daemon to manage, crash or leave behind, and restarts and sub-agents work as before. Given up: about 2 seconds of import per command (measured on the dev machine), plus re-reading stored objects from disk. A Phase-2 workflow is about 10–20 commands. A daemon can be added later as a speed-up without changing the contract.
- **`--help` and `dataforge schema` do not import the heavy dependencies.** They read only the generated help and schemas. Gained: the help layers answer in well under the 2-second import. Given up: help text must be generated ahead of time, and a test must check it is fresh.
- **Flat arguments are flags, and nested arguments are JSON.** Scalars and simple lists are flags (`--seed 7 --exclude-columns a,b`). Nested arguments (`thresholds`, `strategies`, the split `scheme`, the `query_frame` filter) take inline JSON or `@file.json`. A nested argument is validated by the same Pydantic args model, so error `param` paths do not change. Gained: short, readable common calls, and one exact schema for nested input. Given up: two input styles, so `--help` marks which flags take JSON. Dotted flags for every dial were rejected, because about 100 dials would become about 100 flags.
- **Output stays JSON only, with lists of flat records in Table Layout.** stdout is the Wire Record's JSON, byte-stable. A list of flat records goes on the wire as `{"fields": [...], "rows": [[...], ...]}`, with field names written once. A row in Table Layout has at most about 12 fields, and anything wider nests. Code Mode keeps attribute access and `.get(column)`, because only the JSON layout changes. On a stand-in Dataset Digest of 80 columns, one object per row cost 5,893 `o200k_base` tokens. Table Layout cost 2,920, a Markdown table 3,055 and YAML 5,885. Gained: about half the tokens on every table-shaped result, with one format. The Result Budget tests, byte-stability and ADR-0102's "no renderer" all stay. Given up: rows are read by position, `jq` paths are less readable (`.rows[] | .[3]`), and the output schema describes itself less. A text default with `--json` (the playwright-cli style) was rejected, because it brings back a renderer and two formats to test.
- **Floats stay at full precision.** Cutting to about 6 significant digits would save about 16% before Table Layout, about 8% after. Gained: the CLI's JSON and Code Mode's `.to_dict()` stay identical, and glue code computes on exact values. Given up: those tokens.
- **Errors go to stdout, and the exit code names the category.** A Library Error prints its JSON on stdout. The exit codes are `0` for success (even with warnings), `2` `InvalidInput`, `3` `UnknownName`, `4` `Conflict`, `5` `Infeasible`, `6` `IncompatibleArtifact` and `1` `Unexpected`. stderr carries only progress. Gained: one machine-readable stream, so `cmd | jq` works on success and failure alike, and a script can branch on the exit code without parsing. `2` matches argparse's usage-error code. Given up: the Unix habit of errors on stderr.
- **Progress goes to stderr only with `--progress`.** Pipeline Events print one line each to stderr. They are off by default, because every stderr line costs the Agent tokens. `--help` says when a command's cost grows with the data, and the Skill tells the Agent to run those commands in the background or with a longer timeout. Cancelling is killing the process. Write-once atomic Handles mean nothing is left half-written. This closes the open question of how progress reaches a Harness. Gained: no new machinery. Given up: the library cannot stop an Agent from running a long fit in the foreground and hitting the shell's timeout (2 minutes by default in Claude Code).
- **Declared Inputs are opt-in.** With no Declared Inputs in `config.toml`, `load` reads any path. Once the user lists any, `load` refuses every other path with `input_not_declared`. The first command that writes creates `.dataforge/`. There is no `init` step. Gained: the first run just works. Given up: a user who never declares inputs gets no protection and no warning. The Skill and docs say so.
- **Help is layered, and a size number is a signal to split, never a cut.** Each layer is small and names the next layer down:
  - `dataforge --help`: commands grouped by phase, one line each, plus a pointer to the Skill;
  - `dataforge <command> --help`: generated from the seven-part docstring and the schema. It gives the summary, Use when, the flags with type, default and range, the returned fields, the Error Codes, See Also and one Example written as a shell command. A nested argument gets one line plus the command that opens it;
  - `dataforge schema <command> <argument> [path]`: one argument's schema, one level at a time. For example, `dataforge schema profile thresholds` lists the dial groups, and `thresholds.numeric` lists that group's dials.

  When a layer outgrows its token number, it is split into a narrower layer, the same way ADR-0109 split a big Operation. Gained: the Agent reads a short screen at a time and can always go deeper. Given up: more layers to generate and test.
- **The library points to deeper layers of the same data, never to a next step.** `omitted` names the command that returns the rest. `--help` names how to go deeper and lists related commands under See Also, unranked. Results carry no `next` suggestions, and `--help` has no "Next" section. Gained: the Agent plans its own route, without the library's workflow opinion biasing it. Given up: an Agent new to the library leans on the Skill's workflow for orientation.
- **The Result Budget is two numbers, and both are split signals.** A success result is at most 10k `o200k_base` tokens and at most 25,000 characters. A Library Error is at most 8,000 characters. Both are tested on the fixtures. The character limits come from the measured shell caps: Claude Code shows about 30,000 characters inline, and only about 10,000 for a command that exits non-zero. Codex shows 10,000 tokens and Gemini CLI 40,000 characters. An Operation over budget gets a narrower Operation or a smaller default page, never harder truncation. Gained: every result shows inline in every Harness measured. Given up: two numbers to test, and a few detail Operations may get smaller default pages (`describe_columns` may drop from 15 to about 10), which costs extra calls on wide tables.
- **The Strict Subset stays, minus the vendor transformer test.** Its rules split into two groups. Design rules shape the data and stay whatever reads it: no `Any`, strict values, `null` means the default, enums by value, keyed arrays instead of open maps. Printing rules came from vendor strict mode: shared definitions inlined, every field listed as required, limits written as text rather than keywords, `title`, `default` and `examples` dropped, depth and property limits. They stay because limits written as words read better for an Agent in `dataforge schema`, and because they keep MCP a cheap add-back. Only the test that runs schemas through Anthropic's and OpenAI's transformers is deleted. Gained: no churn, since #589 already built and tested the post-pass. Given up: shared records repeat inline in a printed schema. Per-argument printing keeps each print small.
- **The Skill is a command cheat-sheet, installed by the CLI.** `SKILL.md` holds the Handle-chain workflow, one usage line per command, how to iterate on dials, how to act on each error category and exit code, which commands to run in the background, and which Workspace Settings are guardrails. `references/` holds one file per phase, plus `python.md` for Code Mode. `dataforge install --skills` copies the Skill into `.claude/skills/dataforge/` and `.agents/skills/dataforge/`. The second location is read by Codex, Gemini CLI and Cursor. The copy is stamped with the library version, and the CLI warns once when the stamp differs. The folder is named `dataforge`, which is a valid skill name. Gained: it works in every measured Harness, and it survives a venv being moved or deleted. Given up: a copy goes stale after an upgrade until the install is re-run. The version warning covers that. A symlink into `site-packages` was rejected, because it breaks silently when the venv moves.

## Considered Options

- **Keep ADR-0099 as it was (Code Mode plus MCP Tool Calls).** Rejected because the research found no measured Harness reads the catalogue or forwards `input_examples`, Claude Code cuts descriptions at 2,048 characters, Codex strips schema keywords, and every Harness already gives the Agent a shell.
- **CLI only, with Python internal.** Rejected because Python import is free, being the same function, and an Agent writing glue code still wants it.
- **CLI, Code Mode and MCP, all three.** Rejected for now because it keeps #604's whole surface for clients we do not target yet. The shared source keeps MCP a later add-on.
- **A playwright-style daemon with named sessions.** Rejected because our state is already on disk. A browser needs a live process, and we do not.
- **One JSON object per command (`--args '{...}'`).** Rejected because common calls become hard to read in a transcript.
- **A text default with `--json` and `--raw`.** Rejected because it brings back a renderer, two formats, and Literal Fields and `omitted` written as text.
- **Data-driven `next` suggestions on every result.** Rejected because they bias the Agent toward the library's workflow and away from its own reasoning.
- **Errors on stderr.** Rejected because one stream keeps success and failure parseable the same way.
- **A new map for the pivot.** Rejected because the grilling settled every question. What remained was writing, which is not a wayfinder decision.

## Consequences

- ADR-0099: the "no library CLI" decision, Tool Calls, the `[mcp]` extra and the sandbox-based Harness contract are replaced by this ADR. The Operations as the whole public surface, JSON-able inputs and Handles, and one Python source stand.
- ADR-0100: "Tool Calls return the same JSON with `is_error`" becomes "the CLI prints the same JSON and exits with the category's code". An 8,000-character cap is added on each Library Error.
- ADR-0101: the vendor transformer test is deleted, and the Strict Subset's reasons are restated as above. Output lists of flat records use Table Layout.
- ADR-0102: Table Layout is added. The Result Budget becomes two numbers and a split signal. The paragraph on Claude Code's MCP warning points no longer applies.
- ADR-0103: the Workspace defaults to `.dataforge/` and is a Workspace Setting. "Outside the Agent's reach" and "written only by the library and the Harness" are withdrawn as guarantees. Declared Inputs are opt-in.
- ADR-0104: the Dataset Digest and detail lists use Table Layout. Detail page sizes may shrink to meet the character budget.
- ADR-0107: the Literal Policy is a Workspace Setting and a guardrail. `deny` is real only where the Harness stops the Agent from reading the data and from changing the setting.
- ADR-0108: the Skill becomes a CLI cheat-sheet with `references/` and an install command. `--help` replaces the thin Operation file as what the Agent reads per Operation. The file stays the source and the contract for Code Mode. The ~1.5k-token cap becomes a split signal. The docstring's Example is a shell command.
- ADR-0109 is superseded in full.
- ADR-0110: the core budget is a Workspace Setting.
- ADR-0111: `query_frame`'s two deliveries are now the CLI and Code Mode.
- Spec [#588](https://github.com/DEVunderdog/DataForgeML/issues/588) gets a delivery note, and its tickets are realigned. The ticket for the Operation Catalogue and the `[mcp]` server is closed and replaced by a layered-help ticket. A CLI-spine ticket and a Table Layout prefactor are added. The Literal Policy and Package Skill tickets are rewritten.
- `_harness/tool_calls.py` is replaced by the CLI. The contract test driver's Tool Calls leg becomes a CLI leg.
- The version bump is the maintainer's to make.
