# The resumable execution layer is a stateful builder that fits an ImputationDecision unit-by-unit

ADR-0060 unwelded routing from estimation by specifying the pure `ImputationDecision` — the data-free plan. This ADR specifies the other half of the split: the layer that *consumes* that plan and produces trained models. It is deliberately **not** a one-shot `fit()`; it is a resumable builder that trains the plan's materialized `units` one at a time, survives interruption, and lets a caller drive individual units or the whole remainder through a single code path. It is the reference instance of the "execution is a resumable builder" frame charted in the wayfinder map (#333); the phase-agnostic contract is abstracted from it later.

The execution layer is a stateful, mutable **`ImputationExecutor`**, constructed from `(decision, train_df, config, random_seed, observer)`. It holds the immutable decision as its plan and a mutable interior — per-unit state plus the accumulating fitted artifacts. `train_df` is *fuel*: held in memory for the executor's working life, never part of what is serialized, and re-supplied on cross-process resume (the executor is reconstructed from the plan + already-persisted units, not un-pickled whole). This mirrors the stateless-persistence discipline the Evaluation orchestrator already follows (ADR-0057).

Locked decisions:

- **Stateful builder, not a functional fold.** A model-fitting thing that grows as units finish is inherently stateful; forcing functional purity on it buys nothing the immutable *decision* already provides, and it fights thread-pool and Emitter ownership. The decision stays the pure value; the executor is the honest mutable engine.
- **Three-state unit lifecycle with atomic `done`.** Each unit is `pending → running → done`. `running` is transient (meaningless after a stop); `done` requires a *fully* trained artifact. Resume happens **at unit boundaries only, never mid-unit**: an interrupted unit reverts to `pending` and retrains cleanly from scratch. There is no partially-finished unit to resume *into*.
- **Two-track feasibility failure.** ADR-0060 deferred *data-size feasibility* to execution; this is where it fires. An **auto-routed** strategy that cannot train (size guard unmet, or fit error) **falls back** to a simpler strategy (MICE→Median, KNN→Regression→Median), the unit still completes as `done`, and a **Warning Event** records the recovery (ADR-0054). A **user-forced** strategy (per-column override) **raises and stops** — the library's standing "no silent fallback for forced strategies" stance (ADR-0029). A fallback never fragments a unit: the `"mice"` unit that degrades to per-column medians is still *one* `done` unit whose executed outcome simply diverges from the plan.
- **One code path, two entry points.** A single `execute_unit(unit_id)` primitive owns all real work (state transitions, training, fallback, event emission). `execute_all_pending()` is only a driver over that primitive. Re-invoking a `done` unit is a no-op **unless** an explicit `force` / `reset_unit(unit_id)` requests a deliberate retrain.
- **Editing the plan carries over unchanged work.** Because the decision is immutable, changing a column's strategy yields a *new* plan and a *new* executor. That executor is seeded from the prior one's finished units and retrains **only** the units whose id + recipe changed; identical units keep their trained models. Editing-then-rebuilding is cheap rather than all-or-nothing.
- **Two tiers of inference.** A finished unit is a standalone **`FittedUnit`** that can transform *its own columns* immediately, with **no completeness requirement** — the unit is the primary, independently-usable artifact. The **`FittedImputer` is an optional roll-up**: `build()` composes the units into the whole-dataframe imputer, and *only this tier* is gated on completeness (it raises, listing pending units, if any remain), carries the full-schema manifest and whole-frame safety errors (ADR-0024/0026), and projects the untrained dropped/passthrough/indicator records straight from the plan.
- **Progress is unit-scoped and per-drive-call.** The `item` heartbeat counts *units* (not columns); inner block work stays `substep` (ADR-0055). Each drive command builds a fresh Emitter carrying the construction-time observer, with `total` = the units *that command* will run. Extending Per-Call Scoping (ADR-0054), a resumed run reports position among its own units only; whole-plan completion is read off the unit states, never expressed as a global percentage.
- **Concurrency lives in the driver; units are independent by construction.** The thread pool sits in `execute_all_pending`; the single-unit worker is unchanged, preserving one code path. Because a unit is *defined* as an independent chunk (joint models collapsed inside one unit; routing→fit dependency already resolved at decide-time), the entire pending batch parallelizes with no sequencing. State bookkeeping is thread-safe; results are identical to serial via fixed seeds and fold splits (ADR-0056). **`max_workers` is the single control**, and the inner sklearn `n_jobs` is *derived* from the effective outer degree: **wide (`-1`) when the outer degree is 1** (solo unit, hand-invoked, or `max_workers=1`), **pinned (`1`) when >1** — the outer-vs-inner parallelism choice expressed through one knob, avoiding core oversubscription.

## Status

superseded by ADR-0071

The resumable `ImputationExecutor`, its `pending → running → done` state machine, plan-edit carryover, and store-rehydration are retired: map [#377](https://github.com/DEVunderdog/DataForgeML/issues/377) replaces execution with the stateless user-driven `fit_unit` primitive and the `fit_many` / `FittedImputer.compose` wrappers. ADR-0066's degradation amendment to this ADR is retired alongside it.

## Considered Options

- **A pure functional fold** (`execute_unit(decision, unit_id, state) -> new_state`) mirroring the decision's immutability. Rejected: it pushes all driving/bookkeeping (done-set, Emitter threading, thread pool) onto the caller, which just reconstitutes the stateful builder with extra steps; purity buys nothing the immutable decision doesn't already give.
- **`FittedImputer` as the sole inference door** (transform only after everything is trained). Rejected: it couples independent units to a monolith and defeats the layering — a user who trained only the MICE chunk could not transform those columns without waiting for the rest. The two-tier model makes the unit independently usable and demotes `FittedImputer` to an optional aggregate.
- **A separate concurrency-strategy enum** (outer vs inner as an explicit mode). Rejected: `max_workers` already encodes it — `=1` yields inner parallelism (units serial, full inner cores), `>1` yields outer — so a second knob is redundant.
- **Fractional inner allocation** (e.g. 2 units × 4 cores). Deferred: adds tuning complexity for a usually-marginal payoff; the binary pin-or-full rule (ADR-0056) stays the honest default.
- **A `failed` unit state.** Rejected: feasibility failure is resolved *within* a unit (fallback → `done`, or raise → stops), so no terminal failed state is needed; a user-forced raise leaves the unit `pending`, which is exactly right — the executor cannot complete until the plan is edited.

## Consequences

- The keystone the serialization/versioning (#337) and store-identity (#338) tickets persist is now a concrete object: an executor is checkpointed as `(plan identity + the set of done `FittedUnit`s)`, never as a whole pickled builder with a live DataFrame.
- Each strategy's existing fitted object (`_FittedKNN`, `FittedRegression`, the joint MICE/KNN models) is repackaged as an independently transform-capable `FittedUnit`; `FittedImputer.transform` becomes a composition over them rather than the only transform path.
- Whole-frame safety errors (`UnseenColumnError`, split-imbalance warnings) live at the Tier-2 aggregate where the full manifest exists; a `FittedUnit` carries only the narrower "my own columns are absent" contract.
- The public entry point (`decide()` / `execute()` placement at the package root, retiring the fused `fit_transform` / `ImputationOrchestrator` seam per ADR-0050) is still **not** decided here — it graduates from the map's fog once the store tickets settle.
