# The Feasibility Floor filters model-based candidates on two terms

Routing today guards MICE and KNN with raw row and column counts: `mice_min_rows` against `n_rows`, `knn_max_features` against the active width, copied across five *try MICE, else KNN, else Median* chains. A column at 40% missing trains on 60% of those rows, and 500 rows mean different things with 3 predictors and with 50. The **Feasibility Floor** replaces the counts with two quantities that describe what the estimator actually trains on. It is a gate, not a score: no term makes up for another.

## Status

accepted — resolves [What composes the non-compensatory feasibility floor](https://github.com/DEVunderdog/DataForgeML/issues/517) on map #528, re-ratifying its map #516 resolution with the validation loop stripped out. Amends ADR-0079 (`mice_min_rows` is deleted; the `n_nearest_features` gate reads active width) and ADR-0089 (`mice_max_nearest_features` becomes shared by routing and the recipe; `mice_min_rows` and `knn_max_features` leave the gate list). Amended by ADR-0092: the Signal Score and its three tiers are what pick among the feasible candidates, and the routing steps before the escalation point no longer include the `Unpredictable` or `NearConstant` terminals. Amended by ADR-0094: the hungrier estimator's rule is the Estimator Ladder, which reads this floor's Feasibility Terms against its own Estimator Bounds and steps down rather than rejects. Amended by ADR-0097: measurement ([Measure the floor bounds and estimator bounds](https://github.com/DEVunderdog/DataForgeML/issues/543)) leaves one bound, `mice_min_rows_per_predictor = 2`. `mice_min_usable_rows`, `knn_min_usable_rows` and `knn_min_rows_per_predictor` measured trivial and are deleted, so KNN has no floor, only its Resource Ceiling. Usable Rows stays as the numerator of Rows per Predictor.

## Decisions

- **Two Feasibility Terms, per target column.** **Usable Rows** = `row_count · (1 − effective_null_fraction)` of the target. It describes what sklearn trains a column on, not a literature rule (#521 found three incompatible denominators and no reconciliation). **Rows per Predictor** = Usable Rows ÷ predictor count. The shape is defensible; the constants are ours and #519 measures them. Complete-row fraction is rejected: sklearn's KNN donors need not be complete rows (#521). Estimator appetite is not a third term; it is why bounds are keyed by candidate.
- **Named Rows per Predictor, not Rows per Parameter.** KNN has no parameters and a forest's parameter count is not its predictor count. Given up: the link to the "events per parameter" literature, which #521 found weak.
- **The predictor count.** Active numeric columns minus the target (today's `n_features` counts the target). Exclusions already shrink it. For MICE it is `min(active − 1, mice_max_nearest_features)` whenever the `n_nearest_features` cap would apply, and that gate is re-keyed from block size to active width, so routing never reads block membership, which the floor itself decides. `mice_max_nearest_features` is read by routing and the recipe on purpose, like `bimodal_correlation_threshold`. For KNN it is also active width − 1. Given up: the cap is an upper bound on the recipe's real *k*, so the MICE term is still a little strict. **Amended by ADR-0093:** the KNN block reads the full active-numeric predictors, so its count is true as written ([Whether the KNN block reads the full active-numeric predictors](https://github.com/DEVunderdog/DataForgeML/issues/541)).
- **Zero predictors fails Rows per Predictor for both candidates.** No division, no infinite pass. The signal says "no predictors".
- **Four flat bounds.** `mice_min_usable_rows`, `mice_min_rows_per_predictor`, `knn_min_usable_rows`, `knn_min_rows_per_predictor`. `mice_min_rows` and `knn_max_features` are deleted. The MICE bounds track its cheapest estimator (`BayesianRidge`), because the pick of a hungrier estimator sits behind its own rule (#526), so the floor never has to know what the factory chooses. Given up: the floor is lenient for a column that lands on a hungry estimator, and one of the four dials may measure to a trivial value.
- **The Resource Ceiling stays separate, because it reads a different quantity.** `knn_max_rows` guards KNN's memory, which scales with the whole matrix, so it reads the raw `row_count`. The floor reads Usable Rows. A 60k-row column at 90% missing has 6k usable rows and is still refused by KNN on memory. Both remove a candidate the same way. Given up: two named mechanisms that filter alike.
- **No Resource Ceiling for MICE.** #427 measured MICE running out of memory at 5k rows on a 7GB box, but ADR-0079 never moves a column to a cheaper strategy to keep the block small, and `route` stays a pure function of profile and config. Given up: that out-of-memory stays a fit-time problem for the user.
- **Applied at the single model-based escalation point, and nowhere else.** The duplicated chains become: evaluate floor and ceiling for each of `{MICE, KNN}`, keep the feasible ones, and let the signal score and the capability ladder pick (#518, #526). The skew-picked central tendency (Mode for BoundedDiscrete) is always feasible, so the set is never empty. Which routing steps come before this point is #518's, not this ADR's.
- **Per target, not per unit.** A column that fails leaves the block; the block runs for the rest. Given up: no way to say "every column passes but the block is thin".
- **What it returns.** A private helper per candidate returns the failed terms, each with name, value and bound; empty means feasible. The signal names **every** failed term, not only the first. No public record, no feasibility-vs-resource `kind` field: the belief record that needed them is out of scope. Given up: passing terms are visible nowhere.
- **Row count is the routing profile's.** `profile.dataset.row_count` — dev under the hybrid topology (ADR-0088). There is no `n_rows` argument and no split-shape input.
- **Forced columns are evaluated too, inside `route` only.** A column that `per_column_strategy` forces onto MICE or KNN still gets the floor and ceiling; failed terms become a signal on that column (informed consent, ADR-0071). `author` computes no floor. Given up: an authored plan that forces KNN onto a tiny column is not warned.

## Considered Options

- **Every term for every candidate as a lossless value/bound/pass record with a `kind` discriminator** (the #516 answer). Rejected: its readers — the belief record, audit and recommender — are out of scope.
- **A block-level floor.** Rejected: "the block is infeasible" has no consumer, and a column-level failure has one owner.
- **The recipe's real `n_nearest_features` as the MICE denominator.** Most accurate, but circular: it is the median over the block routing is still deciding, and it is resolved after routing.
- **Full active width for MICE regardless of the cap.** Simple, but refuses MICE on wide frames for predictors its equations never use.
- **KNN block width as its denominator.** Truthful to the fitter of the time but circular, and it encoded a fitter shape that #541 then changed (ADR-0093).
- **Rows per Parameter keyed to the hungriest estimator.** Rejected: it refuses columns `BayesianRidge` handles fine.
