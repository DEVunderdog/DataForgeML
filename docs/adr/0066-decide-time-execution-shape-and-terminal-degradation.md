# Size guards decide against the shape execution will face, and execution degrades terminally instead of routing

ADR-0060 made the imputation plan a pure value and ADR-0061 made execution a resumable builder. Both were sound; the code that implemented them was not, and the defect it shipped exposed a genuine gap in the *specification* of where a strategy may be downgraded. This ADR closes that gap. It amends ADR-0061's two-track feasibility clause: the two-track **structure** (auto-routed degrades, user-forced raises) survives intact, but the **fallback chain** it prescribed is deleted. Routing happens once, at decide-time, in the router. Execution never routes.

The premise ADR-0061 rested on was partly false. It specified that fallback fires when a "size guard [is] unmet, or [on] fit error", but a size guard cannot go unmet as a consequence of the router's own choice — the router only ever emits a strategy whose guards already pass, and it *already* walks the fallback chain at decide-time to get there (`_strategy_router.py`; the emitted signals literally read `"knn: regression size guard failed"`, and ADR-0035 fixes that chain as `MARSuspect → MICE → Regression → KNN → Mode terminal`). The executor's chain was therefore a second, hardcoded competitor to the router's, without the routing context to be correct — and it was not correct: its catch-all reached for Median inside the BoundedDiscrete gate, which ADR-0035 forbids outright.

A size guard *could* nonetheless fail at fit time, for one reason only: **`decide()` evaluated guards against the full-dataset row count while the executor trains on the train split**. That was never intended. ADR-0060 specifies the decision as a pure function of `(profile, shape, config)` — shape is an **input**. The implementation instead derived `n_rows` from the profile, and that divergence is what manufactured the gap. Closing it is the load-bearing decision here: once guards evaluate against the shape execution actually faces, the only failure left at fit time is a genuine fit error, and the correct response to a genuine fit error is never "route to something else."

Locked decisions:

- **The plan is decided for the shape execution will face.** `decide(profile, n_rows, config=None)` takes the row count as a **required** parameter, and callers pass the *train* row count. Only `n_rows` is accepted, not the full `(n_rows, n_features, columns)` triple: splitting is row-wise, so `n_features` and the column set remain derivable from the profile and accepting them would only let a caller contradict it. The parameter is required rather than defaulted-to-the-profile because the defect this ADR corrects *was* a plausible default silently producing a wrong answer; a caller genuinely planning against the whole dataset writes `profile.dataset.row_count` explicitly, and that claim then appears in the code and in `decided_for_shape` instead of being assumed.
- **`decided_for_shape` and provenance are different facts and must not share a field.** `decided_for_shape[0]` holds the row count the plan was decided for (the train count); `profile_provenance["row_count"]` keeps the full-dataset count, because provenance describes *the profile*. Their differing is the honest record — "decided for 480 rows, from a profile of 600" — not a contradiction.
- **Execution degrades terminally; it never routes.** A model-based unit that cannot train degrades in **one step** to a scalar — **Mode when `domain_snap_bounds` is present, Median otherwise** — emits a Warning Event (ADR-0054), and completes `done`. There is no `MICE→Median`, no `KNN→Regression→Median`. The surviving trigger is "the target is ~entirely null in the train split", a state in which *no* model of any kind can train, so walking a chain is theatre: KNN→Regression is guaranteed to fail for the reason KNN failed. The one-step scalar is not a simplification but the only truthful answer. `domain_snap_bounds` is sufficient to choose Mode-vs-Median without the router's context, which is precisely why the executor can be trusted with this step and not with a chain.
- **No `fallback_chain` field on the decision.** The router owns the chain; execution's step is fixed and terminal. There is nothing to carry.
- **The plan is never rewritten; the artifact records what it did.** `FittedUnit` gains `executed_strategy` and `degradation_reason` (`None` on the happy path). The executor never mutates a decision. Divergence is a *comparison* — `plan.units[unit_id].strategy != fitted.executed_strategy` — not a stored flag, and `planned_strategy` is deliberately **not** copied onto the artifact: the plan already holds it under the same `unit_id`, and duplicating a fact so it can drift is the failure mode this whole effort exists to correct. The audit trail is (immutable plan) + (fitted units), and under ADR-0029's test nothing lies: the plan says MICE because MICE *was* planned; the unit says it executed Median and why.
- **`forced` is a field on `ColumnImputationDecision`, not a parseable string.** Both producers write it: the router (from `config.per_column_strategy`) and the plan-edit path (`with_column_strategy`). "Was this forced?" is a decide-time fact about the plan, so under ADR-0060 it lives in the plan. The deciding argument is serialization: **a plan loaded from the store must know what was forced without the original config object**, which is impossible while forced-ness lives partly in a config the store does not hold.
- **A forced column raises its whole joint unit, which stays `pending`.** A middle path does not exist: a raise stops execution, so "degrade the others, raise for this one" describes no achievable run; and the unit cannot be split, because MICE is joint by definition. ADR-0029 settles the remainder — the forced column's declaration is unsatisfiable, and an unsatisfiable declaration raises. The unit staying `pending` is what makes this cheap: the user un-forces the column and ADR-0061's carryover retrains only that unit. The error names the forced column(s). **Note the surprising corollary, recorded here deliberately rather than left to be discovered:** forcing a column to the strategy the router would have chosen anyway is a decide-time no-op that nonetheless flips execution from degrade to raise. This is intended — forcing is a declaration of requirement, not a routing hint, and the router's agreement does not erase it.
- **Degrade-vs-raise is the user's policy.** `ImputationConfig.on_fit_error: "degrade" | "raise"`, default `"degrade"`. Raise-always is the more principled stance and a poor default: `"degrade"` keeps an unattended run completing, `"raise"` serves the pipeline that would rather halt than ship a Median where MICE was planned. The library cannot derive which the caller is from the data, which is the signature of a legitimate dial. Two hard boundaries: **`"degrade"` does not mean "never raise"** — forced strategies raise regardless, as that is ADR-0029 and not a preference the knob may switch off; and the degradation **target** (Mode-if-bounded-else-Median) is **not** configurable, following from ADR-0035 and the data rather than from taste.

## Status

partially retired by ADR-0071

The **degradation** half of this ADR is retired: with execution now a stateless user-driven primitive (map [#377](https://github.com/DEVunderdog/DataForgeML/issues/377)), an untrainable unit raises `UnitNotTrainableError` unconditionally — there is no terminal degradation-to-scalar, no `on_fit_error` knob, no auto-routed/forced two-track, and no `FittedDegradedJoint`/`executed_strategy`/`degradation_reason`. The **routing-correctness** half *survives*: `decide(profile, n_rows, config=None)` still evaluates size guards against the train row count, execution still never routes, and `decided_for_shape`/`forced` remain as specified.

## Considered Options

- **Keep the decide/execute row gap and absorb it as an execution-time fallback**, leaving `decide()` a pure function of the profile alone. Rejected: it forces the executor to make a routing decision it lacks the profile context to make correctly, which is exactly the defect that produced the ADR-0035 violation. Its one real merit was tolerating cross-validation folds of differing row counts under a single plan; that is answerable — fold row counts differ by a rounding error, not by a size-guard threshold, and a plan decided for the smallest fold is safe for all of them.
- **An optional `n_rows` defaulting to `profile.dataset.row_count`.** Rejected: that default *is* the gap, reinstated as the behaviour you get by forgetting. It would also have let every existing call site keep passing while testing the wrong row count — the precise shape of the original failure.
- **Accept the full `(n_rows, n_features, columns)` shape triple**, matching ADR-0060's vocabulary literally. Rejected: only the row dimension varies under a row-wise split, so the other two would exist solely as a way to contradict the profile.
- **Raise on any fit error; no degradation at all**, letting ADR-0061's plan-editing carryover be the sole recovery path. It is the more principled position and was rejected only as a *default* — a 200-column overnight run dying on column 173, for a column the profiler would likely have flagged `DropCandidate` anyway, is a poor trade, and a Warning Event plus a recorded divergence is not the "silent fallback" ADR-0029 prohibits. Preserved as `on_fit_error="raise"` rather than foreclosed.
- **Re-invoke the router at fit time with the failed strategy excluded**, so execution-side fallback inherits full routing context. Rejected: it is the *correct* way to build a chain, but it adds an exclusion-set API to the routing kernel to serve a case that, once the row gap is closed, reduces to "no model can train" — where a chain has nothing to offer.
- **Keep the legacy rewrite-in-place record** (`_fallback_to_median` replacing `decision.strategy` and appending a `"fallback_to_median: <reason>"` signal), so a record stays self-describing. Rejected: it makes the plan and the record disagree about what was *planned*, and demotes original intent to prose recoverable only by prefix-matching a string — the same string-sniffing anti-pattern this ADR removes from forced-detection.
- **Copy `planned_strategy` onto `FittedUnit`** so divergence is readable from one object. Rejected: self-containment is what licensed the lie; two fields holding one fact is how they drift.

## Consequences

- **`decide()` becomes split-then-plan rather than plan-then-split.** A plan is valid only for a given split size, and re-splitting invalidates it. This is arguably what `decided_for_shape` always meant, but it makes plan reuse across splits an error rather than a convenience, and `decide(profile)` is no longer a standalone planning act.
- **Two latent bugs are fixed as a by-product, neither previously known.** `n_rows` is not only a guard input but a hyperparameter input (ADR-0062): `n_neighbors = min(adaptive_raw, n_rows - 1, ...)` currently bounds against the *full* dataset, so a plan can legally request more neighbours than the train split contains. And `with_column_strategy()` forcing was invisible to the executor's `config.per_column_strategy` lookup, so a plan-edited force degraded silently instead of raising — an ADR-0029 violation reachable through the public plan-edit API.
- **Three schema changes land and must be batched into one identity/version step, not three**: `decided_for_shape` semantics, `forced`, and the two `FittedUnit` members. This touches the shipped store work (ADR-0063/0064; issues #358, #362). Pre-release, so no compatibility burden.
- **Reading the audit trail now requires two artifacts.** "What happened to column X" is no longer answerable from one self-contained record; it needs the plan and the unit together. A genuine ergonomic loss, accepted because self-containment is what permitted the record to misreport intent.
- **The `FittedUnit` Protocol widens for every implementer**, including the four that can never degrade and will hardcode `degradation_reason = None`.
- **A degraded unit remains a real quality cliff.** A column planned as MICE completing as a Median scalar is a large accuracy drop, and a Warning Event is easy to miss in a long run. `on_fit_error="raise"` is the answer for callers who cannot accept that.
- **Mode-vs-Median via `domain_snap_bounds` is a proxy, not the real predicate.** It holds because bounds are populated exactly for `NumericKind.BoundedDiscrete`, but no type enforces that coupling; if bounds are ever populated for another reason, the branch mis-fires silently. `ColumnImputationDecision` carrying `NumericKind` directly would close this and is deliberately not done here.
- **`ColumnImputationRecord` loses its decision-rewriting role**, leaving it looking like a legacy shape. Its fate belongs to the `FittedImputer` reshape (#349/#353) and is deliberately not settled here.
- **Deleting the chain forecloses a future case**: if a strategy is ever added that can fail for a reason a *simpler model* would survive, chaining must be reintroduced — at decide-time, in the router.
- `_execute_fallback` is deleted outright. The correct Mode/Median branch already exists in the legacy path and is relocated, not reinvented.
