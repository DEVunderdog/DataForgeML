# Persistence collapses to bare polymorphic `serialize`/`deserialize`/`inspect` free functions; the store port and content-addressed identity are removed

ADR-0063 specified the wire form of each persisted object and the version-gated reconstruction contract; ADR-0064 added the abstract `ArtifactStore` port (dumb documents+blobs), content-addressed keying (`SHA-256(data_fingerprint + config + library_version)`), a full-content `data_fingerprint`, load-for-reuse relevance validation (`ArtifactIdentityMismatchError`), and the manifest-last crash-safety discipline. Both were the reference instances of the "storage-agnostic store + cache identity" frame charted in map [#333](https://github.com/DEVunderdog/DataForgeML/issues/333). This ADR **supersedes ADR-0064 and narrows ADR-0063**, resolving [Collapse persistence to serialize/deserialize (#381)](https://github.com/DEVunderdog/DataForgeML/issues/381) on map [#377](https://github.com/DEVunderdog/DataForgeML/issues/377).

Everything ADR-0064 added existed to serve two things that no longer exist: **cross-process resume** (retired with the resumable executor, ADR-0071) and a **deferred persistence service** (still deferred, and now explicitly not pre-built here). Content-addressed keying was resume cache-lookup; the `data_fingerprint` and `decision.identity()` were the keys; the store port was the service's DB seam; manifest-last was the store's crash-safety. With resume gone, storage becomes the user's plain business: hand them bytes, take bytes back.

Locked decisions:

- **One uniform surface: three exported free functions.** `serialize(obj) -> bytes`, `deserialize(data) -> FittedUnit | ImputationDecision | StructuralProfileResult`, and `inspect(data) -> dict`. `serialize` accepts any of the three persistable kinds; `deserialize` is **polymorphic**, dispatching on a `kind` tag in the envelope; `inspect` reads the envelope header **without unpickling**, so a caller can check compatibility and provenance before trusting the payload into an unpickle. The `save(store, key)` / `load(store, key)` methods on `FittedUnit`/`FittedImputer` are removed; storage location, naming, and lifecycle are the user's.
- **The store port and the identity module delete wholesale.** `_store.py` (the `LocalFileStore` default), the `ArtifactStore` / `DocumentStore` / `BlobStore` port protocols in `_serialization.py`, and `_identity.py` (`fitted_unit_identity`, `decision.identity()` support) are removed entirely. Storage is not the library's concern; identity/content-addressing was resume's concern and resume is gone.
- **The envelope is readable JSON; only the unit carries an opaque tail.** Every serialized object is a JSON envelope (kind tag, schema version, `library_version`, and — for the unit — the `produced_with` six-version stamp and the payload SHA-256) followed, for the `FittedUnit` only, by an opaque joblib payload. Decision and profile are pure data structures and serialize as JSON alone, carrying only the **light** stamp (schema version + `library_version`) — there is nothing to unpickle, so they need no reconstruction gate. The `FittedUnit` keeps the **heavy** gate from ADR-0063: `produced_with` and the SHA-256 are verified **before** the joblib tail is unpickled.
- **There is no aggregate format.** `FittedImputer` has no `serialize`; a whole imputer is persisted as its decision plus its units, and **rehydrated via `FittedImputer.compose(decision, units)`** (ADR-0071). This keeps exactly one leaf binary format — the unit's joblib tail — and removes the base64-in-JSON nesting the old aggregate manifest used. Composition's exact-coverage check (ADR-0071) is what guarantees a rehydrated imputer is structurally complete.
- **Provenance/verification is dropped — the flagged open decision, resolved toward removal.** `data_fingerprint` (its only job was resume cache-keying and load-for-reuse relevance) and `decision.identity()` (content-addressing) go. `ArtifactIdentityMismatchError` and any `verify_identity` path delete. "Was this unit trained on the data I think it was?" is no longer checked at load: it was only ever meaningful for *reusing* a cached unit against a re-supplied frame, which is the resume path that no longer exists. Structural correctness is instead enforced at composition by exact-coverage; `produced_with` survives strictly as the **reconstruction** guard (can these bytes be safely unpickled under the installed sklearn/numpy/joblib?), never as a **relevance** guard.
- **The trust boundary is unchanged.** Per ADR-0063: unpickling is arbitrary-code-execution, and the SHA-256 is an integrity check (did the bytes survive transport intact?), never authenticity (were they written by someone you trust?). `deserialize` on a `FittedUnit` runs the reconstruction checks first and unpickles only trusted-origin bytes; this ADR narrows *what else* is checked, not the ACE posture.
- **Manifest-last crash-safety dies with the store.** It existed because a `FittedUnit` was two store writes (blob + manifest) needing crash-atomicity without transactions. A serialized unit is now **one blob** the user writes wherever they like, so there is no two-write window and nothing to make atomic. The `data_fingerprint` output the Phase 1 profiler emitted for keying is removed from the profiler.

## Status

accepted

Supersedes ADR-0064. Narrows ADR-0063 (reconstruction gate survives on the `FittedUnit`; the wire form moves to a JSON envelope + single joblib tail; the aggregate manifest and base64 nesting are removed). Consumes the charting leans of #381.

## Considered Options

- **Keep content-addressed keying as a provenance/verification aid even without resume.** Rejected: without a store to key into and without a reuse path to validate against, the fingerprint and identity are cost with no consumer — a full-content frame hash computed for a check nothing runs. Structural completeness, the one property that still matters, is answered by composition's exact-coverage.
- **Keep a typed `save_unit`/`load_unit` pair over a minimal store.** Rejected: every backend would re-learn the wire format (the ADR-0064 objection), and there is no longer a service to justify the port at all. Bare `bytes` in / `bytes` out lets the user pick any storage with zero library involvement.
- **Give `FittedImputer` its own aggregate serialize format.** Rejected: it duplicates the unit format one level up (base64-nesting the leaf blobs into a manifest) and creates a second thing to version. Decision + units + `compose` reconstructs the whole with one format and one code path.
- **Keep `ArtifactIdentityMismatchError` as a soft warning on load.** Rejected: there is no load-for-reuse moment left to warn at — `transform` never checked identity even under ADR-0064, and reuse-against-a-different-frame is the resume path that is gone. A check with no trigger is dead code.
- **Serialize the whole envelope as joblib (no JSON split).** Rejected: `inspect` must read provenance and compatibility *without* unpickling (the pre-unpickle gate is the whole safety story); a JSON header over an opaque tail is what makes header-inspection possible without ACE.

## Consequences

- **`_store.py` and `_identity.py` are deleted**; `_serialization.py` is rewritten around the three free functions and loses the store-port protocols. `ArtifactStore` and `LocalFileStore` drop from `dataforge_ml.__init__` (and their `__all__` entries); `ArtifactIdentityMismatchError` drops from the exceptions export. `serialize`, `deserialize`, `inspect` are added to the Public API (documentation-scoped under ADR-0034).
- **The Phase 1 profiler loses its `data_fingerprint` output** and the whole-frame hash it computed for keying. `StructuralProfileResult` drops the fingerprint field.
- **`_fitted_persistence.py` collapses**: the content-addressed `save_fitted_unit_addressed` / `load_fitted_unit_addressed` helpers (and the executor methods `persist_to_store` / `rehydrate_from_store` that called them, already gone with ADR-0071) are removed; what survives is the unit's envelope encode/decode, now reached through `serialize`/`deserialize`. **Amended:** that survivor was subsequently absorbed into `_serialization.py` as `_encode_fitted_unit` / `_decode_fitted_unit`, and `imputation/_fitted_persistence.py` deleted. Hollowing the module out had left it with *no* imports from the imputation package — it encodes a unit purely by duck-typing (`type(unit).__name__`, `unit.target_columns`) — so its address under `imputation/` recorded only where it was born, while its round trip with `_serialization.py` was the package's one import cycle, survivable only because both edges were deferred into function bodies. The persistence boundary is therefore **one root module**: `serialize`/`deserialize`/`inspect`, the envelope framing, the version gate, and the single opaque-payload encoder all live in `_serialization.py`, whose imports of `ImputationDecision` and `StructuralProfileResult` are now ordinary top-level ones. The dependency arrow runs root → phase and never back; a phase package importing `_serialization` would now raise `ImportError` at import time rather than be silently absorbed.
- **`ArtifactPythonVersionWarning` and `IncompatibleArtifactError` survive** as the reconstruction-gate signals on the `FittedUnit` path; they remain exported.
- **The hyperparameter override delta must ride in the decision envelope.** ADR-0073's sparse override map is state on the plan that is not reconstructible from `decide()`, so `serialize(decision)` must persist both the decided base and the delta; `deserialize` restores a plan that re-stamps the same merged hyperparameters.
- **The deferred service, if ever built, re-derives storage and identity itself.** Naming/alias layers, multi-writer status, and content-addressing were already ADR-0064's "inherited by the service"; they are now the service's wholesale, with the library shipping only the wire format.
