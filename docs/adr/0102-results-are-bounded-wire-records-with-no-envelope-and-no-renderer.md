# Results are bounded Wire Records, with no envelope and no renderer

ADR-0101 made every Operation return an output Wire Record, whose `.to_dict()` is exactly the Tool Call JSON. This ADR decides what sits on top of that. The research asked for a result envelope (`status`, concise vs detailed, `truncated`, `warnings`, `next`), a `to_dict()` on ten Result Types that had none (G3), and a text format picked by eval. It also asked what happens to `to_markdown()` now that humans are not users. The answer: no wrapper, no renderer, one bounded shape per Operation, and warnings as data.

## Status

accepted. Resolves [What does every library result look like to an Agent?](https://github.com/DEVunderdog/DataForgeML/issues/574) on [Map: an agent-native DataForgeML](https://github.com/DEVunderdog/DataForgeML/issues/568). It supersedes ADR-0086 and amends ADR-0100, ADR-0074, ADR-0054 and ADR-0055. Amended by ADR-0109: the default Result Budget is 10k. Planning only: no code changes yet.

**Amended by [ADR-0112](0112-agents-reach-the-library-through-a-cli-and-a-skill.md) (2026-10-11).** A list of flat records goes on the wire in Table Layout (`{fields, rows}`, field names once, at most about 12 fields per row), which halved the tokens on a stand-in Dataset Digest. The Result Budget becomes two numbers: at most 10k `o200k_base` tokens and 25,000 characters for a success result, and 8,000 characters for a Library Error. A result over budget is split into a narrower Operation or a smaller page, never cut harder. The CLI prints the JSON on stdout. Pipeline Events print to stderr only with `--progress`.

## Decisions

- **G3 dissolves. Internal types get no `to_dict()`.** Each internal result converts to its output Wire Record at the boundary, and that record is the only serialisation path. A Payload Frame never goes into a Wire Record. The Agent gets a handle to it instead. Gained: one path, so enum name-vs-value drift cannot come back. Given up: an internal object cannot be dumped for debugging without going through the boundary.
- **The library emits JSON only. `to_markdown()`, `__str__` delegation, the Rendering Contract, Result Type, Fragment and the Profile Report are deleted.** ADR-0086 is superseded. `__repr__` stays as Pydantic's short default. A Harness that wants Markdown, CSV or anything else for its model renders it from the JSON. Gained: one format to test, and no 394k-token `print(profile)` trap in Code Mode. Given up: the research said the text format should be picked by eval. Any format other than JSON is now the Harness's job, and the measurement ticket checks JSON only.
- **There is no envelope.** Every output Wire Record inherits a few standard fields from one base record: `warnings` and `omitted`. There is no `status`, because ADR-0100 already separates success from failure (raise in Code Mode, `is_error` in Tool Calls). There is no `result` wrapper. Gained: flat records, so Code Mode reads `result.units`, not `result.result.units`, and a generic Harness finds warnings in the same place every time. Given up: nothing in the record says which Operation produced it. The call already says that.
- **One bounded shape per Operation. No concise/detailed flag and no `fields` selection.** Each Operation returns the concise shape. Detail comes from separate, narrower Operations over a handle. Gained: one output schema per Operation, bounded by construction, which is the same progressive disclosure ADR-0099 uses for the Skill. Given up: more Operations, and one extra call when the Agent needs detail. A flag would double every output schema and force detailed-only fields to be `null` in concise mode, which breaks ADR-0101's rule that `null` means default.
- **Results are bounded by construction, and a test proves the budget.** Every list field in an output record has a fixed maximum item count. A cut list is recorded in `omitted`. Nothing is counted in tokens at runtime, and nothing is cut as bytes. The default budget is **10k tokens per Operation result** (raised from 8k by ADR-0109), measured with `tiktoken`'s `o200k_base` offline in a test, on fixtures at the scale the library supports (the 81-column House Prices table plus a synthetic wide table). An Operation may declare a lower budget, never a higher one. ADR-0099's Harness output cap stays as the backstop. Gained: a capped record still matches its schema, the cut is deterministic, and what was left out is named. Given up: caps are counts, not tokens, so long column names can push a result over budget. Only the fixture test catches that, and only for the fixtures we pick. `o200k_base` is a stand-in for Claude's tokenizer, which is why the budget sits far below Claude Code's 25k cap.
- **`omitted` says what was cut and where the rest is.** It is `[{field, shown, total, operation}]` and appears only when something was cut. `operation` names the Operation that returns the rest, without arguments. In Tool Calls, Anthropic's API never shows the model an output schema, so a field description cannot carry this. A test checks that every `operation` names a real Operation. Gained: an Agent is never left with a cut list and no way forward, and the field costs nothing when nothing was cut. Given up: a cross-reference inside the data that must be kept correct. Ready-to-run arguments were rejected because they could carry their own errors, and the library would be guessing what the Agent wants next.
- **The rest of a list is reached by filters, then paging.** Detail Operations take filters (column names, flagged only, a kind) plus `offset`/`limit`, with `limit` at most the cap. There are no cursors. Gained: everything is reachable, and every call is stateless and repeatable. Given up: more parameters, though under the Strict Subset they are `null` by default.
- **The most actionable items come first.** Warnings come before notes, flagged columns before clean ones, and C2ST `Flagged` before `Passed`. Ties go in dataset column order. Each capped field states its sort rule in its description. Gained: the first 20 items are the ones that matter. Given up: a sort rule per field to define and test, and output order no longer follows the CSV.
- **Warnings are data only.** A warning is a subset of the Library Error shape: `code`, `message` and optional `columns`, `param`, `hint`. It follows the same caps and the same names-only rule, and leaves out fields it never fills (`candidates`, `allowed`). Every warning code is an entry in the Error Code registry, marked `warning` instead of a category. The stdlib `warnings.warn` calls, `ImputationFitWarning` among them, are removed. Gained: one channel and one registry, and nothing reaches the model by a side door the library does not cap. Given up: a Harness that only watches stderr sees nothing.
- **`FitSignals` keeps its facts and loses its warnings.** The estimator, `converged`, `n_iter` and the merged dials stay as typed fields on the fit Operation's output. Its `warnings` move into the standard `warnings` field, under codes such as `mice_not_converged`. Fit duration leaves the wire, because time belongs to the Harness (ADR-0099) and it breaks byte-stable output. Gained: one place to look for warnings. Given up: the time per unit.
- **C2ST outcomes are never copied into `warnings`.** A per-column outcome is the measurement itself and stays per-column data. The C2ST result gets an outcome census at the top. The fixed MAR caveat leaves the result and goes into the Operation's docstring. Gained: no duplicate records to drift apart, and no fixed paragraph paid for on every call. Given up: an Agent that reads only `warnings` misses flagged columns. The census is what makes them hard to miss.
- **Pipeline Events are progress only.** The `warning` and `decision` event types are dropped (nothing emits `decision` today). How progress reaches a Harness is open on the map, because a live `observer=` callable cannot cross the Operation boundary. Gained: one channel for warnings. Given up: a long profile run cannot show a warning until it returns.
- **Floats are not rounded.** The library emits full precision. A Harness rounds for display if it wants. Gained: Code Mode glue computes on exact values, and both deliveries emit the same JSON. Given up: more tokens per float in Tool Calls.
- **The serialisation is byte-stable. The ML is not promised to be.** Given the same underlying result, the library writes the same JSON: keys in schema order, lists in their fixed sort order, and no timestamps or run ids unless a field exists to hold one. A test serialises one result twice and compares. This does **not** promise that an Operation run twice on the same input produces the same result. Model fits, thread order and seeds decide that, and it is out of this contract (see ADR-0067). Gained: Harness prompt caching works, and snapshots are trivial. Given up: no `generated_at`-style metadata on results.

## Considered Options

- **Add `to_dict()` to the internal types (the research's upstream fix for G3).** Rejected: a second serialisation path beside the Wire Records.
- **A generic library renderer (compact Markdown or YAML-like text) on the Wire Record base.** Rejected: a second format to test, chosen without the eval the research asked for.
- **A generic `{result, warnings, truncated, next}` wrapper.** Rejected: it adds nesting and repeats what ADR-0100 already says about success.
- **A `response_format` flag, or a `fields` selection.** Rejected for the reasons above.
- **A runtime byte cap that cuts the serialised JSON.** Rejected: a cut record no longer matches its schema. **No library cap at all:** rejected because ADR-0099 promises bounded results.
- **Keeping `warnings.warn` beside warnings as data.** Rejected: a second, uncapped channel.

## Consequences

- ADR-0086 is superseded outright. The losslessness test it moved onto `to_markdown()` goes with it.
- ADR-0100 is amended: the error record's `truncated` count becomes the same `omitted` list, so results and errors share one word and one shape.
- ADR-0074 is amended: `FitSignals.warnings`, the `ImputationFitWarning` double channel and `duration_s` on the wire are removed.
- ADR-0054 and ADR-0055 are amended: Warning Events and `decision` events are gone, and the event stream is progress only. How progress reaches a Harness joins the map's fog.
- ADR-0034's rule that every `to_markdown()` needs a docstring lapses, since none remain.
- The handles ticket inherits the Payload Frame, and the inventory ticket inherits the concrete detail Operations each `omitted` points at.
