# Handles are write-once ids into a Workspace the Harness provides

ADR-0099 says Operations take and return only JSON-able values and handles, in both deliveries. ADR-0102 says a Payload Frame always comes back as a handle. This ADR decides what a handle is. Frames, the profile (about 394k tokens on Ames), fitted units (up to 127 MB) and the composed imputer can't enter the model's context. Over Tool Calls the library only ever receives a string, so something in the library's process must turn that string back into an object. The real choice was memory or disk, and how long a handle lives.

## Status

accepted. Resolves [How does an Agent refer to large objects across calls?](https://github.com/DEVunderdog/DataForgeML/issues/575) on [Map: an agent-native DataForgeML](https://github.com/DEVunderdog/DataForgeML/issues/568). It amends ADR-0072 and ADR-0096 (the persistence functions become internal) and ADR-0099 (the Harness contract). Planning only: no code changes yet.

**Amended by [ADR-0112](0112-agents-reach-the-library-through-a-cli-and-a-skill.md) (2026-10-11).** The Workspace defaults to `.dataforge/` in the working directory and is a Workspace Setting: a flag beats an env var, which beats `.dataforge/config.toml`, which beats the default. "Set outside the Agent's reach" and "written only by the library and the Harness" are withdrawn as guarantees, because in a shell the Agent can change them. Enforcement belongs to the Harness's permission rules. Declared Inputs are opt-in: with none listed, `load` reads any path. The first command that writes creates the Workspace. Each CLI command is its own process, which this ADR's multi-process design already supports.

## Decisions

- **Handles live in a disk Workspace.** The Harness gives the library a writable directory. Every handle is written there when it is made, and cached in memory. Execution stays run-less (ADR-0071, ADR-0075): `fit_unit` still keeps no lifecycle state. The Workspace is storage, not a run. Gained: handles survive a process restart, any process pointed at the same directory can use them, and both deliveries behave the same. Given up: a disk write on every result (fitted units can reach 127 MB), and a required directory in the Harness contract. This brings back a small store, which ADR-0072 deleted because it had no consumer. An Agent working across processes is that consumer.
- **The Harness sets the Workspace once, outside the Agent's reach.** That means an environment variable, or a startup argument to the MCP server. No Operation names a directory. Gained: the Agent can't point the library at a directory it shouldn't, and the trust boundary below relies on this. Given up: one process works on one Workspace, and Code Mode can't compare two.
- **A handle is a plain string: a kind prefix plus an opaque id**, such as `frame_7f3a9c2e`. It is the same value in Code Mode and Tool Calls. Each Wire Record field states the kind it expects in its description, and the boundary checks it. Gained: cheap ids, readable kinds that make clear errors possible, and one representation, so one test covers both deliveries. Given up: no dedupe, no names chosen by the Agent, and no static typing in sandbox code.
- **Handles are write-once.** A handle always points at the same object. Any Operation that "changes" something returns a new handle. Gained: safe sharing with no locks, repeatable calls, and nothing goes stale. Given up: disk space, since old versions stay until the Workspace is deleted.
- **Anything a later Operation consumes or reads detail from gets a handle.** That includes frames, the profile, routing, recipe, fitted units, the imputer, and results that have detail Operations, such as a C2ST report. JSON-sized values travel by value. The exact list belongs to the Operation inventory.
- **Frames never change after load.** Dropping a column happens through config, as an exclusion. There are no frame-editing Operations and no way to register a changed frame. Gained: every change to the data is a decision on the record, and a hallucinating Agent can't reshape the data. Given up: ad-hoc reshaping. An edit config can't express is not possible.
- **`load` reads only input paths the Harness declares.** These are set up the same way as the Workspace. Any other path raises `input_not_declared` (`InvalidInput`). The Harness mounts declared inputs read-only. Gained: the rule above actually holds in Code Mode, where the Agent's code could otherwise write an edited CSV and load it. Given up: a second legitimate file needs the Harness to declare it.
- **`export_frame(frame)` writes CSV into the Workspace's `exports/` folder and returns the path.** The Agent never picks the destination. Gained: one format, matching the CSV-only scope, and no writes outside the Workspace. Given up: dtype fidelity, since a re-read of the CSV may infer types again.
- **A handle lives as long as the Workspace.** There is no TTL and no release Operation. The Harness deletes the directory when it is done, because ADR-0099 gives all resources to the Harness. Gained: no dangling references and no new failure mode. Given up: control over disk inside a session. A tuning loop that fits many large units fills the disk, and only the Harness can stop it.
- **Bad handles raise typed errors.** `unknown_handle` (`UnknownName`) covers a handle that was never made, was mistyped, or whose file is gone. Its candidates are existing handles of the same kind, capped and newest first. `wrong_handle_kind` (`InvalidInput`) names the expected and the given kind. A handle written by another library or format version raises `IncompatibleArtifact`, and the strict load from ADR-0096 is unchanged. There is no "expired" error, because handles don't expire. Gained: every handle error tells the Agent its next move. Given up: candidate lists cost tokens, though the cap bounds them.
- **The imputer handle is a manifest.** `imputer_…` points at one recipe handle and its unit handles, and the imputer is composed again on use. Nothing aggregate is pickled, so ADR-0072 stands. Write-once means the parts can't change under it. Gained: no new artifact format and no second copy of large units. Given up: each process pays to compose again the first time it uses the imputer.
- **`serialize`, `deserialize` and `inspect` become internal: the Workspace's on-disk format.** No Operation hands out artifact bytes or takes them in. To move work elsewhere, copy the Workspace directory. Gained: no bytes on the wire, and no import path for foreign pickles. Given up: no way to hand one fitted unit to an unrelated Workspace.
- **The library unpickles only files inside its own Workspace.** The Harness contract states that only the library and the Harness write to the Workspace. The checksum in each header catches corruption, not tampering. Gained: a rule that is simple and true. Given up: no protection if the Agent's sandbox code writes into the Workspace itself. That is the Harness's to prevent.
- **Many processes may share one Workspace.** Write-once handles, random ids and atomic writes (write to a temp file, then rename) need no locks. Sub-agents get the Workspace from the Harness. Gained: parallel sub-agents for free. Given up: two processes that fit the same unit make two handles.
- **`list_handles(kind=null)` lets an Agent find its handles again.** Each handle's record stores its lineage (the Operation that made it, the arguments it was called with as passed, and the handles it was made from; arguments added by ADR-0104) and a short size summary. The list is bounded and paged, newest first, as ADR-0102 requires. Gained: an Agent can recover after a restart or as a sub-agent, and lineage is ready for later script export. Given up: one more Operation and a little metadata on every write.

## Considered Options

- **An in-memory registry only.** It is fast and simple. Rejected: every handle dies with the process, and a sub-agent in another process can't use it.
- **The Harness holds handles and the library returns bytes.** Rejected: bytes aren't JSON (ADR-0099), and Tool Calls would push 127 MB through the Harness.
- **Content-hash handles.** These would dedupe repeated loads. Rejected: model fits aren't deterministic (ADR-0067), so the hash promises nothing for most kinds, and hashing large units costs time.
- **Names chosen by the Agent.** Agents handle names better than ids. Rejected: names bring collisions and overwrite rules, and these fight write-once.
- **File paths as handles.** Rejected: the layout would become the contract, and the Agent would start editing files directly.
- **A typed handle wrapper in Code Mode.** Rejected: it is a second representation, and Tool Calls still carry a string.
- **Registering changed frames (frame Operations, a CSV reload hatch, or `register_frame(df)` in Code Mode).** Rejected: each gives the Agent a way to change the data outside the record. `register_frame` also breaks parity between the two deliveries.
- **A `release` Operation.** Rejected: it raises the question of what happens to handles built from a released one, and disk is the Harness's resource anyway.
- **A keyed signature (HMAC) on pickles.** Rejected: anyone who can write the directory can usually read the key too.

## Consequences

- ADR-0099's Harness contract gains:
  - a writable Workspace, set outside the Agent's reach, written only by the library and the Harness;
  - declared input paths, mounted read-only.
  The line "if handles turn out to need one" is settled: they do.
- ADR-0072 and ADR-0096 are amended. The three functions and the four saved kinds remain as the Workspace format. They are no longer public, and the bytes are no longer the user's to place.
- G8's "foreign bytes" case disappears from the public surface, since no Operation takes bytes in. A decode failure inside the Workspace still has to be a Library Error, not a bare `JSONDecodeError`.
- G4 and G7 are answered by handles: split frames are frame handles, and the imputer is a manifest handle.
- The map's "Sub-agent fit" fog shrinks: handles are shareable across processes. Whether every Operation is safe to run in parallel stays open.
- Today's user-owned drop step (ADR-0077) has no Operation. A hard exclusion is honoured inside the library instead of by the Agent dropping the column.
