# A dtype floor for consumers — no active column arrives as `pl.String` unless it is Text or Identifier

The type detector labels a column's *meaning* and the frame carries its *encoding*, and the two were never made to agree. A column profiled `SemanticType.Categorical` commonly sits in the frame as `pl.String`; so does one stamped `Boolean` from `"yes"`/`"no"`, and one stamped `Datetime` from a coercion attempt whose result was measured and then discarded. Every consumer downstream of profiling has therefore been reading a dtype that contradicts the semantic type it was handed, and each has patched around it privately or not at all.

We adopt a **dtype floor**: *no active column reaches a consumer as `pl.String` unless its semantic type is `Text` or `Identifier`.* Each non-string semantic type names the dtype it materialises as — `Categorical` → `pl.Categorical`, `Boolean` → `pl.Boolean`, `Datetime` → `pl.Datetime`/`pl.Date`, `Numeric` already enforced by the detector's coercion path. The floor is enforced **constructively at each phase entry**, immediately after `_resolve_effective_nulls`, by one private function in `utils/` driven off the profile. Nothing asserts it and there is no public predicate: the library fixes the frame on the way in.

## Status

accepted — a peer of ADR-0087, not a section inside it.

## Locked decisions

- **The rule is a floor for consumers, not a biconditional.** It was first written as `SemanticType.Categorical ⇔ pl.Categorical`, which is both too narrow and too wide. Too narrow: `pl.String` columns are also stamped `Boolean` and `Datetime`, and all three crash `HistGradientBoostingClassifier` with the identical `ValueError: could not convert string to float` — the exemption those two semantic types appeared to deserve belongs to the *dtype*, never to the semantic type. Too wide: `SemanticType.Categorical` is also assigned to integer columns carrying `TypeFlag.EncodedCategory`, and those stay `pl.Int*`. Phrasing the rule as an equivalence would have dragged the int-coded half into a cast ADR-0087's seam deliberately declined to make.

- **Enforced at each phase entry, not at load.** The five call sites are the existing `_resolve_effective_nulls` sites — profiling's orchestrator, `fit_unit`, `FittedImputer.transform`, splitting's profile signals — plus evaluation's. This is the pattern the repo already runs: nothing is cached, every phase re-derives a working copy from the profile and throws it away, and the user's frame is never mutated. `DataLoader` is ruled out on facts rather than preference — it has no profile, and only the detector can separate a Categorical string from a Text string. The detector cannot do it either: it returns `ColumnTypeInfo`, not a frame. Given up: the cast runs on every call rather than once, so a wide categorical table pays it repeatedly, and there is no single normalised artifact anyone can inspect.

- **ADR-0078 stays satisfied for free.** `_restore_observed` reassembles from the *input* frame, so the cast is invisible at the boundary and observed cells still come back bit-for-bit in their original dtype.

- **Cast silently, never raise, and do not warn.** Under this placement the cast is a dtype detail of an internal working copy, not a decision the user is being kept from — and a warning would fire on virtually every real frame, which trains people to ignore warnings. Given up: nothing tells a user their string column was treated as categorical, beyond the profile that already says so.

- **`_sentinel_eligible` is widened to accept `pl.Categorical`, and the cast is ordered after null resolution.** Measured on `['x','y','NA','  ','x',None]`: as `pl.String` the column resolves **3** effective nulls, as `pl.Categorical` it resolves **1** — sentinel and whitespace matching stop working entirely. Ordering fixes the library's own path, but a user may legitimately hand in an already-`pl.Categorical` frame, and then the sentinels are lost with no recourse. `_null_detection.py` calls itself the single authority on what counts as effectively null and was giving a wrong answer for a dtype `_data_types.py` already lists in `_CAT_DTYPES`. Cost: sentinel matching on a Categorical means a cast to Utf8 and back inside `_resolve_effective_nulls`.

- **`TypeDetector` routes `pl.Categorical` down the string path.** Today a Categorical column falls past every string branch to the fallback and is classified `SemanticType.Text` — a live bug for anyone loading dictionary-encoded Parquet, independent of evaluation, and the thing that would make this rule non-idempotent (cast at the source, re-profile, and every categorical becomes Text). Behaviour change worth naming: the string path's cardinality heuristics now run against a dtype whose entire point is low cardinality, so a Categorical column will essentially never be flagged as free text. Arguably correct; still a change.

- **A failed coercion is an effective null.** `.cast(pl.Categorical)` is total and lossless; Boolean and Datetime are not. Datetime re-runs `_try_datetime_coerce` with `strict=False`, so unparseable values become null; Boolean re-derives from `_BOOL_STRING_SET`, so a token outside it (`"Y"` where profiling saw only `"true"`/`"false"`) becomes null too. The library already holds exactly this position for `"NA"`, empty strings, `Inf` and declared sentinels. Rejected: **raising** when the phase-entry coercion rate falls below the profile's — it turns a data-quality issue into a hard stop mid-fit, on the same frame-dependent heuristic that caused the problem. Rejected: **recording the observed token→bool mapping** on `ColumnTypeInfo` and raising on an unseen token — stricter and more honest, but it adds a field every phase reads for a case that only bites when the serve frame's vocabulary drifts.

## Consequences

- **The null count at phase entry can exceed the profile's recorded missingness.** A column's missingness rate is a profile-time fact that phases may legitimately disagree with. For C2ST those rows are filed into pile B — they were filled, so that is the right pile, but the pile is not exactly the profile's null count.
- **A genuine typo (`"ture"`) is silently absorbed as missing** rather than surfaced. The accepted cost of the looser rule above.
- **Constructive, not checked.** A runtime assertion could only ever fire on library code that forgot to call the normaliser, which is what tests are for. Users never need to ask "does my frame satisfy this?"
- **Confirmed unaffected:** `_fitters.py`'s MICE predictor-widening guard (`is_numeric()` returns `False` for both `pl.Boolean` and `pl.Categorical`, so a materialised column is excluded from the joint matrix exactly as its string form is today); the correlation profiler, which already casts defensively to Utf8 then Categorical; and GroupWise's fill map, keyed off string values regardless of physical encoding.
- **ADR-0087's `pl.String` guard changes job.** Since `Text` and `Identifier` are dropped as features and as targets, no `pl.String` column can reach the generic `c2st` through `evaluate_imputation` at all. The named error becomes a defensive guard for direct callers of the private generic, not a path the adapter can trip.

## Found while implementing (#508)

- **The coercing profilers are exempt from profiling's own floor.** Inside the profiling orchestrator the only consumer of the phase-entry frame is the per-`SemanticType` profiler batch, and for `Boolean` and `Datetime` that profiler *is* the coercion authority — it alone applies the user's declared `datetime_formats` and `datetime_epoch_units`, it raises `OverrideCoercionError` when a declared type coerces to nothing, and it flags **Format Mismatch** by counting the values that survive coercion. Handing it a floored frame breaks all three: the floor's generic `str.to_datetime` cannot parse a bare `"%Y"` year the user declared a format for, and every unparseable value it nulls is dirt the profiler can no longer see. So the floor is applied at profiling's entry as decided, and those two profilers read the null-resolved, pre-floor frame. Nothing else in the phase reads that frame, so the exemption is invisible outside profiling. Measured: without it, six existing profiling tests fail.

- **`_preserve_observed` does *not* cover the floor for free at `FittedImputer.transform`.** The ADR's claim was that the seam reassembles from the input frame, so the cast is invisible at the boundary. It only fires *inside* each model-based unit, over that unit's own numeric columns — precisely the columns the floor never touches. Left alone, `transform` returned a `pl.Categorical` column where the caller handed in `pl.String`, a public dtype change. `transform` therefore hands its floored columns back through `_preserve_observed` against the pre-floor frame on the way out: observed cells come back bit-for-bit at the input dtype, and a filled cell keeps its fill rendered into that dtype. The floor stays a detail of the working copy, which is what ADR-0078 requires.
