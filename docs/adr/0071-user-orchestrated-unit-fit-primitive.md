# Execution is a stateless user-driven `fit_unit` primitive plus two thin wrappers; the resumable builder and its degradation policy are retired

ADR-0061 specified execution as a stateful, resumable `ImputationExecutor` — a `pending → running → done` state machine that trained a plan unit-by-unit, survived interruption, carried finished units across plan edits, degraded untrainable auto-routed units to scalars, and rolled the finished units up through `build()`. ADR-0066 amended its feasibility clause (execution degrades terminally, never routes). Both were the reference instances of the "execution is a resumable builder" frame charted in map [#333](https://github.com/DEVunderdog/DataForgeML/issues/333). This ADR **supersedes ADR-0061 and retires ADR-0066**: the resumable builder is removed and replaced by a stateless primitive the user drives themselves. It is the spine of map [#377 — Simplified user-orchestrated execution layer](https://github.com/DEVunderdog/DataForgeML/issues/377), resolving [User-driven unit-fit primitive (#379)](https://github.com/DEVunderdog/DataForgeML/issues/379), [Convenience wrapper: fit-many + compose-to-whole-frame (#380)](https://github.com/DEVunderdog/DataForgeML/issues/380), and [Retire the leftover NumericImputer engine (#378)](https://github.com/DEVunderdog/DataForgeML/issues/378).

The resumable builder existed to serve a deferred persistence service (store-rehydration, cross-process resume). That service is still deferred, and map #377 concludes the machinery it demanded is not worth carrying in the library today: the pure decision layer (ADR-0060), decision-carried hyperparameters (ADR-0062), and the `FittedUnit` serialization contract (ADR-0063) all survive; what goes is the state machine, the store-rehydration, the degradation policy, and the whole `ImputationExecutor` object. The user becomes the orchestrator.

Locked decisions:

- **A stateless free-function primitive replaces the executor.** `fit_unit(decision, unit_id, df, *, random_seed=None, n_jobs_inner=-1) -> UnitFitResult` lives in a new `_unit_fit.py`. It normalises the frame (ADR-0068 sentinel maps read off the plan), builds the `UnitFitContext`, dispatches to the strategy fitter, and returns a `UnitFitResult` bundling the trained `FittedUnit` with its `FitSignals` (ADR-0074). There is no object to construct, no `train_df` held in memory, no `pending/running/done` lifecycle, no `execute_unit`/`execute_all_pending`/`reset_unit`/`force`, no `prior_executor` carryover. Editing a plan and re-fitting is the user's loop, not the library's state to preserve — because the decision is already the immutable value that carryover was reconstructing. The internal `_fitters.fit_unit` dispatcher is renamed `_dispatch_unit_fit` to free the public name; the engine → fitters dependency edge is unchanged.
- **Untrainable is single-track: it raises, always.** A unit that cannot train raises `UnitNotTrainableError` carrying a structured payload (the unit id, its strategy, the columns, and the underlying fitter reason). There is **no** degradation-to-scalar, **no** `on_fit_error` knob, **no** `FittedDegradedJoint`, **no** forced-vs-auto two-track. ADR-0066's degradation policy is retired wholesale: the auto-routed/forced split existed only because degradation existed, and once nothing silently swaps a strategy the two tracks collapse into one honest raise. The caller catches it and edits the plan (`with_strategy`) — the same recovery ADR-0066 already prescribed for the forced case, now the only case.
- **The forced-strategy size guard is killed, not reintroduced.** ADR-0061's executor blocked a user-forced strategy whose data was too small (KNN over `knn_max_rows`, regression under `regression_min_rows`). That guard is gone and must **never** be re-added to `decide()` or the primitive: forcing a strategy past its routing threshold is informed consent, not an error to block. The oversize condition is *observed* and *warned* rather than *refused* — [Per-unit observability (#383)](https://github.com/DEVunderdog/DataForgeML/issues/383) reconstructs it structurally in the fitters and emits an `ImputationFitWarning`. A genuine fit failure still raises `UnitNotTrainableError`; being forced past a routing threshold, on its own, does not.
- **Concurrency is a stateless `fit_many` wrapper, not a builder.** `fit_many(decision, df, *, unit_ids=None, max_workers=None, random_seed=None) -> dict[str, UnitFitResult]` is a free function beside `fit_unit`. It normalises the frame **once** (not per unit — the skew this introduces into per-unit `duration_s` is documented in ADR-0074) and drives the selected units through the private `_dispatch_unit_fit`. `max_workers` remains the single ADR-0069 layer switch: at one worker units fit serially and each opens inner sklearn parallelism to every core (`n_jobs_inner=-1`); above one worker units fit side by side, each inner estimator pinned (`n_jobs_inner=1`), so the two layers never oversubscribe. `fit_many` is **fail-fast**: the first `UnitNotTrainableError` raises clean, with no partial-result dict and no signals attached to the exception. There is no live-progress callback (`on_unit_complete` and a revived `Emitter` were both rejected); a user who wants per-unit progress writes the `fit_unit` loop themselves.
- **Aggregation is `FittedImputer.compose`, a stateless named constructor.** `FittedImputer.compose(decision, fitted_units)` replaces `ImputationExecutor.build()`. It is a classmethod, **tolerant** of either `FittedUnit` or `UnitFitResult` inputs (it unwraps the latter), and enforces **exact coverage**: every unit the plan materialises must be supplied exactly once, and a missing or extra unit raises rather than silently under-imputing. It inherits everything `build()` uniquely owned — the structural-column projection (Dropped, Passthrough, and the MNAR `{col}_missing` Indicator columns, read straight from the plan) and the whole-frame guards (`UnseenColumnError`, the Passthrough-violation check) that a single `FittedUnit` has no standing to raise (ADR-0024, ADR-0026).
- **Units are now uniform, because scalars are `FittedUnit`s.** With degradation gone, a scalar-strategy column is a `FittedScalar` unit like any other, so `FittedImputer`'s internals simplify: `records` loses its `fill_value` field and becomes a pure structural manifest (which columns exist, which are dropped/passthrough/indicator), and the `models` + `model_cols` pair collapses into **one ordered `units` list** applied in plan order (ADR-0067). The dual "scalar-via-record vs model-via-unit" application path that `build()` needed — and the `_PLAN_SCALAR_STRATEGIES` / degraded-scalar disambiguation it rested on — is deleted. Scalar-as-unit persistence is settled by [Collapse persistence to serialize/deserialize (#381)](https://github.com/DEVunderdog/DataForgeML/issues/381).
- **The leftover `NumericImputer` engine is deleted.** With the executor gone there is one fitting path (`_dispatch_unit_fit`), so the duplicate `NumericImputer.fit()` engine and its degradation/fill helpers (`_fallback_to_*`, `_resolve_fill_value`) delete outright. Three helpers relocate to where the surviving code lives: `_mice_winning_tag` → `_decision_assembler`, `_MODEL_BASED_STRATEGIES` → `_config`, `_resolve_fit_workers` → `_fitters`.

## Status

accepted; the `fit_many` batch-driver decision is superseded by ADR-0075 (`fit_many` removed; batch scheduling is user-owned) — `fit_unit`, `FittedImputer.compose`, and everything else here stands

Supersedes ADR-0061. Retires ADR-0066 (degradation policy and the auto/forced two-track no longer exist). Consumes and finalises the charting leans of #378, #379, #380.

## Considered Options

- **Keep the resumable builder for the deferred service.** Rejected: the service is still deferred with no committed shape, and carrying a state machine, store-rehydration, and a degradation policy against a hypothetical consumer is exactly the speculative generality map #377 exists to remove. The pure decision (ADR-0060) already gives resume its only durable input; a service, if built, can reconstruct a driver over `fit_unit` without the library shipping one.
- **Keep degradation as an opt-in `on_fit_error="degrade"`.** Rejected: degradation's whole purpose was to keep an *unattended resumable run* completing. With the run now user-driven and synchronous, the caller is present to catch a raise and edit the plan — and a silent Median where MICE was planned is the accuracy cliff ADR-0066 itself flagged. Raise-always was the more principled stance in ADR-0066 and becomes the only stance here.
- **A `fit_many` that returns partial results on failure.** Rejected: a partial `{unit_id: result}` dict with one unit missing is a silent-under-imputation trap — the user would have to diff it against the plan to notice. Fail-fast raises the one error that matters; a user wanting per-unit tolerance writes the `fit_unit` loop and catches per iteration.
- **Fold `compose` into a free function like `fit_unit`.** Rejected: `compose` constructs a `FittedImputer`, so a named constructor (`classmethod`) keeps the construction on the type it produces and reads as the aggregate's other entry point beside `deserialize`-rehydration; a bare free function would orphan it from the class it builds.
- **Re-add the size guard as a hard block on forced oversize.** Rejected explicitly and permanently: it is the ADR-0029 "no silent fallback for forced work" stance inverted into "no forced work past a threshold," which the library has no basis to impose. Observability (ADR-0074) warns; it never blocks.

## Consequences

- **`ImputationExecutor`, `UnitState`, and the whole `_executor.py` module are deleted**, and their exports (`ImputationExecutor`, `UnitState`) drop from `dataforge_ml.__init__` and `dataforge_ml.imputation`. `UnitNotTrainableError` survives, relocated to `_unit_fit.py` and re-exported. The public shape becomes `decide()` → edit → `fit_unit`/`fit_many` → `FittedImputer.compose` → `transform`, with the user owning the loop between the middle two.
- **`FittedDegradedJoint` is deleted**, and `FittedScalar` loses `executed_strategy`/`degradation_reason` — the divergence-recording fields ADR-0066 added exist only for a degradation that no longer happens (the serialized-field cleanup is executed by #381, ADR-0072).
- **`decide()` keeps its ADR-0066 shape** — `decide(profile, n_rows, config=None)`, guards evaluated against the train row count — because that decision was about *routing correctness*, orthogonal to whether execution is resumable. Only the executor-side fallback ADR-0066 also deleted is affected, and it is already gone.
- **The audit trail is still (immutable plan) + (fitted units)**, but nothing on a unit now diverges from the plan: a unit trained exactly the strategy the plan named, or it raised. "What happened to column X" reads off the plan alone for intent and the `FitSignals` (ADR-0074) for the fit's runtime facts.
- **Observability moves from an event stream to a returned record.** The executor's `Emitter`/Warning-Event degradation reporting is gone; per-unit runtime facts ride back on `UnitFitResult.signals` (ADR-0074) instead. This is a deliberate narrowing of the imputation-execution observability surface, not of profiling's.
- **Tests coupled to the executor lifecycle** (`execute_all_pending`, `reset_unit`, `force`, resume, degradation, `on_fit_error`) are removed or rewritten against the `fit_unit`/`fit_many`/`compose` surface. Pre-release, so no compatibility burden.
