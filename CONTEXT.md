# DataForgeML Domain Glossary

## Pipeline & Phases

- **Pipeline** — An ordered sequence of **Phases** that transform a dataset from raw input to ML-ready features.
- **Phase** — A discrete stage of the pipeline with a specific responsibility. Currently defined phases are:
    1. **Profiling** — Structural analysis and type detection.
    2. **Imputation** — Handling missing values.
    3. **Outlier Detection** — Identifying and handling extreme values.
    4. **Normalization** — Transforming distributions (e.g. Log, Box-Cox).
    5. **Encoding** — Converting categorical data to numeric.
    6. **Scaling** — Rescaling numeric features.

## Column Exclusions

- **Hard Exclusion** — The declaration that a column is out of the pipeline entirely: excluded columns are invisible to every phase's logic. Managed via `exclude_columns`, a read-only view over a private, setter-only-mutable field. `PipelineConfig.add_exclusion(column)` (accepts a single name or a list) is the programmatic entry point for promoting columns into the Hard Exclusion set — used by `FittedImputer.apply_exclusions` to propagate Phase 2 `DropCandidate` columns into all downstream phases. The library never physically removes a hard-excluded column from any DataFrame — **dropping is user-owned**: in Phase 2, `decide()` omits the column from the plan entirely (recoverable via the plan's `config_snapshot`), and if the user has not dropped it from their frame by transform time, `FittedImputer.transform`'s strict unknown-column raise (`UnseenColumnError`) is the enforcement backstop. See ADR 0023, ADR-0044, ADR-0077.
- **Soft Exclusion** — Bypassing the logic of one or more phases for a specific column while retaining that column in the dataset. Declared explicitly via `PipelineConfig.add_phase_exclusion(phase, column)`, not by writing to `phase_exclusions` directly (a read-only view). Enforced by each phase's own entry point (see the **Phase Active-Columns Contract**): a column soft-excluded for the Imputation phase appears in the plan as `Passthrough` with a signal recording the exclusion, and its missing values ride through `transform` untouched rather than raising. Distinct from assigning `SemanticType.Identifier`, which is a type-routing decision, not an exclusion declaration. See ADR-0044, ADR-0077.

## Phase Orchestration

- **Phase Orchestrator** — The single entry point for a Phase. Owns all column routing, exclusion, and sequencing decisions for that phase. Calls `PipelineConfig.resolve_active_columns` to obtain the active column set and hands sub-processors only pre-decided column lists. Sub-processors hold no configuration reference and trust the column list they receive completely. For Phase 1, the Phase Orchestrator is `StructuralProfiler`. Phase 2 has **no** Phase Orchestrator: the Decision/Execution split replaced that fused seam with the user-orchestrated `decide()` → `fit_unit()` → `FittedImputer.compose()` door (ADR-0060, ADR-0071). Its responsibilities did not vanish with the class — routing and exclusion enforcement live in `decide()` (which resolves the Imputation-phase active columns itself, per the **Phase Active-Columns Contract**), parameter estimation in the stateless `fit_unit` primitive, and roll-up in `FittedImputer.compose`. See ADR-0077.
- **Phase Active-Columns Contract** — Every phase entry point — orchestrator or door — must resolve its own active columns for its own phase via `PipelineConfig.resolve_active_columns`; no phase may rely on an upstream phase having filtered for it. The responsibility attaches to *being an entry point*, not to a particular class, so deleting or restructuring a phase's entry seam can never orphan exclusion enforcement again. Binds the future entry points of Phases 3–6. See ADR-0077.
- **Sub-processor** — A focused computation unit within a phase (e.g. `NumericProfiler`, `MissingnessProfiler`). Receives `(DataFrame, list[str])` and profiles exactly those columns — no routing, no eligibility checks, no access to `ProfileConfig` or `PipelineConfig`. If a sub-processor needs a computation parameter (e.g. a threshold), it receives a **Phase Sub-Config** in its constructor — a purpose-built parameter bundle containing only that sub-processor's threshold constants. The Phase Sub-Config carries no routing state; all routing and eligibility decisions remain with the Phase Orchestrator. See ADR-0002, ADR-0030.
- **Imputation Fitter** — A strategy-scoped fit function within Phase 2, living in `_fitters.py` and dispatched by `fit_unit` on the unit's `ImputationStrategy`. Receives a normalised `train_df` plus the plan-carried recipe for one `ImputationUnit` and returns a `FittedUnit`. Replaces the SemanticType-keyed sub-processor registry (`NumericImputer` and `_IMPUTATION_REGISTRY`), which the Decision/Execution split removed: routing is settled at decide-time, so the fit layer dispatches on the decided strategy rather than re-deriving anything from semantic type. Columns whose semantic type has no imputer are decided as `Passthrough` and produce no unit.

## Configuration

- **PipelineConfig** — The master configuration object for the entire pipeline. Cross-phase: owns global exclusions, phase exclusions, column type overrides, references to each phase's Sub-Configuration, and `random_seed: Optional[int]` (seed for all stochastic pipeline operations, including GMM Sampling during bimodal imputation; `None` produces non-deterministic output). Lives at the package root, not inside any phase module.
  _Avoid_: pipeline settings, global config
- **Phase Config** — A specialized configuration object (e.g. `ProfileConfig`, `ImputationConfig`) that holds parameters relevant to exactly one phase. Nested inside `PipelineConfig` as a named field. Phase configs are phase-owned; they live in their respective phase module. Threshold configurability is scoped to the phase that owns the threshold: definitional thresholds (e.g. what counts as `MissingSeverity.High`) live in the phase that *produces* the label; operational thresholds (e.g. `knn_max_rows`) live in the phase that *consumes* it. Phase Configs may nest **Phase Sub-Configs** — one per sub-processor — composed as named fields (e.g. `ProfileConfig.missingness`, `ProfileConfig.numeric`) carrying only the threshold constants owned by that sub-processor. Orchestrator-level thresholds that no sub-processor owns (e.g. `row_drop_threshold`, `memory_threshold_mb`) remain as top-level fields on the Phase Config directly. See ADR-0030.
  _Avoid_: sub-config, modular config
- **Phase Sub-Config** — A purpose-built parameter bundle for a specific sub-processor within a phase. Contains only the threshold constants that sub-processor uses to produce its labels. Passed to the sub-processor's constructor by the Phase Orchestrator, which extracts it from the corresponding field on the Phase Config. Carries no routing state, exclusions, or cross-phase signals — those remain in `PipelineConfig` and `PhaseConfig`. Phase Sub-Configs for Phase 1: `MissingnessProfileConfig` (`ProfileConfig.missingness`), `NumericProfileConfig` (`ProfileConfig.numeric`), `NonlinearityProfileConfig` (`ProfileConfig.nonlinearity`), `TypeDetectionConfig` (`ProfileConfig.type_detection`), `CategoricalProfileConfig` (`ProfileConfig.categorical`), `CorrelationProfileConfig` (`ProfileConfig.correlation`), `DatetimeProfileConfig` (`ProfileConfig.datetime_`). The term "shared config object" in ADR-0002 refers to `ProfileConfig` and `PipelineConfig` — sub-processor constructors may accept a Phase Sub-Config. See ADR-0030.
  _Avoid_: profiler config, sub-processor config
- **SplitConfig** — The configuration object for `DataSplitter`. Carries `max_stratification_signals` (cap on the stratification label matrix width) and `boolean_minority_threshold` (minimum true/false ratio for a boolean column to generate a stratification signal). Nested on `PipelineConfig` as `split: SplitConfig`. `DataSplitter.__init__` accepts an optional `SplitConfig`, defaulting to `SplitConfig()`. See ADR-0030.
- **Column Override** — An explicit `SemanticType` assignment for a named column stored in `PipelineConfig.column_overrides`, bypassing auto-detection for that column in all downstream phases. Set via `set_column_type(column, type)`, which accepts either a single column name or a list of column names sharing the same type. `column_overrides` itself is a read-only view; storage is a private `dict[str, SemanticType]` (column → type) mutable only through the setter. The override is not validated against the column's actual dtype at set time — validation happens at profiling time, when the target profiler attempts coercion. If a `Datetime`, `Boolean`, or `Numeric` override yields zero usable values from a column that had non-null data, the profiler raises `OverrideCoercionError` rather than silently dropping the column or returning empty/degenerate stats. For a `Datetime` override whose string format Polars cannot infer, declare the format via `set_datetime_format` (see **Datetime**) to avoid the total-coercion failure; for a numeric epoch column, declare the unit via `set_datetime_epoch_unit`. See ADR-0043, ADR-0044, ADR-0045, ADR-0046.
  _Avoid_: type override, manual type
- **Declarative Config Field** — Any per-column/per-scope config field a caller populates before running the pipeline (e.g. `column_overrides`, `numeric_sentinels`, `mnar_columns`, `per_column_strategy`). Always private-backed, exposed only as a read-only view (`MappingProxyType` for dict-shaped fields, `tuple` for list-shaped fields), and mutable only through exactly one validating setter per field — never by writing to the field directly. Setters validate what's checkable within their own object; cross-object rules are re-checked by a `validate()` method the owning orchestrator calls before running, not by the setter itself. See ADR-0044.
  _Avoid_: config field, settable field
- **resolve_active_columns** — A centralized method in `PipelineConfig` that calculates the final set of columns a phase should process by reconciling hard exclusions, phase-specific soft exclusions, and the available data. Under the **Phase Active-Columns Contract**, every phase entry point calls it for its own phase. See ADR-0077.
- **Public API** — The set of names importable directly from `dataforge_ml` (the package root), governed by one rule: **a symbol is Public API if and only if the user must reference it to configure, drive, or handle the pipeline.** Concretely this covers (1) phase entry points (`StructuralProfiler`, `DataSplitter`, `DataLoader`, `EvaluationOrchestrator`, `FittedImputer`, and the layered imputation door — `decide`, `fit_unit`, `UnitFitResult`, `FittedUnit` — which replaced the fused `ImputationOrchestrator` per ADR-0060/0071; there is no batch wrapper, batch scheduling is user-owned per ADR-0075); (2) every config object the user constructs or nests, including all Phase Sub-Configs (`ProfileConfig` and its seven sub-configs, `ImputationConfig`, `NumericImputationConfig`, `SplitConfig`); (3) **input enums** — enums the user passes into a config setter or field (`SemanticType`, `Modality`, `PipelinePhase`, `NumericKind`, `ImputationStrategy`, `ModelChoice`); (4) result and nested-record types users hold or type-hint (`StructuralProfileResult`, `ColumnProfile`, `DatasetStats`, `ImputationResult`, `ColumnImputationRecord`, `ImputationDecision`, `ColumnImputationDecision`, `SplitResult`, `FoldResult`, `HoldoutCVResult`); (5) user-facing evaluation reports and their per-column diagnostics (`InspectionReport`, `InspectionDiagnostic`, `AccuracyReport`, `AccuracyDiagnostic`), plus the per-fit observability record `FitSignals`; (6) the observability surface a user consumes or supplies (`PipelineEvent`, `EventType`, `stderr_observer`); (7) the three persistence free functions (`serialize`, `deserialize`, `inspect` — ADR-0072); and (8) exceptions and warnings the user catches (`UnseenColumnError`, `FittedColumnAbsentError`, `UnfittedColumnError`, `OverrideCoercionError`, `UnsupportedFormatError`, `IncompatibleArtifactError`, `UnitNotTrainableError`, `ArtifactPythonVersionWarning`, `ImputationFitWarning`, `DroppedColumnAbsentWarning`). Excluded — accessible via submodule imports only — are **output-only internal types**: enums that classify output but are never user-supplied (`TypeFlag`, all `*Flag`/`*Tag`/`*Severity` enums, `EpochUnit`, `CorrelationMethod`, `TargetType`) and per-modality stats dataclasses. The test is user-supply, not reachability: `NumericKind` is Public because the user sets it via `set_numeric_kind`, whereas `TypeFlag` is internal because it only ever appears as computed output on `ColumnProfile`. See ADR-0050.
  _Avoid_: exported names, top-level imports

## NonlinearityTag

A per-column signal computed by Phase 1 (`NumericProfiler`) and stored in `NumericStats`. Captures the degree to which the relationship between a numeric column and its predictors departs from linearity. Used by Phase 2 to auto-select the estimator inside the unified MICE chained-equations `IterativeImputer`.

- **Linear** — Pearson ≈ Spearman across predictors; mutual information consistent with linear dependence; R² gap between linear and tree model is small.
- **MonotonicNonlinear** — Spearman rank correlation significantly exceeds Pearson; relationship is non-linear but monotonic.
- **ComplexNonlinear** — high mutual information not explained by Pearson or Spearman alone; R² gap confirms tree model meaningfully outperforms linear model; relationship has non-monotonic or interaction-driven structure.
- **Unpredictable** — both linear and tree model R² are near zero (< 0.1); no model family provides meaningful uplift over a scalar fill. Acts as an **unconditional pre-routing guard** in Phase 2: regardless of missingness mechanism (MCAR, MAR) or severity, the column routes to Median and no model-based strategy is attempted. The MAR mechanism may still be real, but if no numeric predictor achieves meaningful R², model-based imputation produces no uplift over a scalar fill. Recorded in `ColumnImputationRecord.signals`. See ADR-0016. **Exception (bimodal):** when `NumericFlag.Bimodal` is also set and no correlated features are available, the column routes to GMM Sampling instead of Median — GMM Sampling fills from the distribution shape and is not subject to the R² guard. See ADR-0032.

Computed from four signals, all always applied: (1) Spearman/Pearson discrepancy, (2) `mutual_info_regression`, (3) R² gap test (LinearRegression vs shallow RandomForestRegressor on complete rows), (4) Breusch-Pagan heteroscedasticity test on linear model residuals. Phase 2 uses this tag first as a pre-routing guard (`Unpredictable` → Median, unconditionally), then as an estimator selector for non-Unpredictable columns: `Linear` → `Pipeline([StandardScaler, BayesianRidge])`; `MonotonicNonlinear` → `RandomForestRegressor`; `ComplexNonlinear` → `GradientBoostingRegressor` (large datasets) or `RandomForestRegressor` (small).
  _Avoid_: non-linearity score, linearity flag

## NumericKind

The discrete/continuous classification of a numeric column, computed by `NumericProfiler` and stored in `NumericStats.numeric_kind`. Lives in `models/_data_types.py` because both Phase 1 (profiling) and Phase 2 (imputation strategy routing) consume it.

- **BoundedDiscrete** — a numeric column whose values form a closed, finite set. Classified by a compound four-signal test applied in `_classify_numeric_kind` (Phase 1); all four signals must pass: (1) tight sequence — observed values fill every integer slot between min and max (`range_span == n_unique`); (2) small range — `max - min ≤ 20`; (3) low cardinality — `n_unique / n_rows < 0.05` OR `n_unique ≤ 10` (the floor protects small datasets); (4) standard origin — `min == 0 or min == 1`. For float columns, an additional pre-check is required: all non-null values must be whole numbers (`value % 1 == 0` for all values); float columns with any fractional values are always `Continuous`. `n_rows` is passed into `_classify_numeric_kind` to support signal 3. In Phase 2, BoundedDiscrete columns are captured at **Priority 3** (the BoundedDiscrete gate) and run their own sub-chain: MAR and MCAR routing apply normally, but every model-based prediction is **domain-snapped** (`clip(round(prediction), min, max)`) to enforce the finite domain. Mode is the terminal fallback when all model-based size guards fail, and also the unconditional fill for `Unpredictable` and `NearConstant` sub-cases where no model-based uplift is available. Snap bounds (`NumericStats.min`, `NumericStats.max`) are stored in `ColumnImputationRecord.domain_snap_bounds` at fit time so `transform()` can apply the snap without the profile. NearConstant minority defined by exact equality to mode value. **Exception (bimodal):** when `NumericFlag.Bimodal` is also set, the Bimodal Imputation Framework applies inside the BoundedDiscrete gate. Branches 1 (grouping variable → Cluster-Conditional), 2 (many correlated features → `_mar_strategy(severity=High)`; Median terminal replaced by Mode), and 3 (few correlated features → Cluster-Conditional with cluster mode fill) apply with normal strategy assignments; domain-snap still applies to model-based predictions. Branch 4 (no correlated features, or `feature_correlation` is `None`) routes to **Mode** — sampling a continuous GMM into a finite discrete domain is semantically inappropriate even with snapping. When `NonlinearityTag.Unpredictable` is also set, the Unpredictable guard fires first inside the sub-chain (step a, before the bimodal check at step c) and the column routes to Mode. See ADR-0035 (amends ADR-0018), ADR-0032.
- **Continuous** — all other numeric columns. Includes integer-typed and integer-valued float columns that fail any of the four signals above. NearConstant minority defined by values outside `mode ± 0.5 * IQR`.
  _Avoid_: integer column, categorical numeric, discrete column

## TailAsymmetryTag

A per-column signal computed by Phase 1 (`NumericProfiler`) and stored in `NumericStats.tail_asymmetry_tag`. Captures the asymmetry between the extreme right and extreme left tails, derived from the existing `PercentileSnapshot` as a bounded share: `(p99 - p95) / ((p99 - p95) + (p5 - p1))`. The raw share is stored as `NumericStats.tail_asymmetry_share` (range `[0, 1]`); `None` when both bands are flat (`p5 == p1` and `p99 == p95` — no spread on either side to compare). A flat left band alone (`p5 == p1`) with a non-flat right band is well-defined (`share = 1.0`, maximal `RightHeavy`) and does not produce `None`.

- **RightHeavy** — right extreme tail is significantly heavier than the left (share > `tail_asymmetry_right_share_threshold`, default `2/3`, configurable in `NumericProfileConfig`)
- **LeftHeavy** — left extreme tail is significantly heavier than the right (share < `tail_asymmetry_left_share_threshold`, default `1/3`, configurable in `NumericProfileConfig`)
- **Symmetric** — both extreme tails are balanced

For routing: `RightHeavy` or `LeftHeavy` upgrades the effective `SkewSeverity` by one level at routing time (stored severity unchanged). Provides finer signal than `SkewSeverity` alone — a `SkewSeverity.Moderate` column with a disproportionately heavy extreme tail is escalated to KNN the same as `SkewSeverity.Severe`. See ADR-0033, ADR-0041.
  _Avoid_: tail ratio, asymmetry ratio, tail_asymmetry_ratio

## NumericFlag

A set of per-column diagnostic annotations computed by Phase 1 (`NumericProfiler`) and stored as a list on `NumericStats.flags`. Used in Phase 2 routing via `NumericStats.has_flag(flag)`.

- **ScaleAnomaly** — column values span an anomalous number of orders of magnitude, suggesting unit mixing or data quality issues.
- **NearConstant** — mode frequency exceeds `near_constant_threshold` (default 90%): 90%+ of values share the same value. Caps distribution shape escalation in Phase 2 — model-based imputation learns near-constant predictions regardless of tail shape, so escalation is wasted. De-escalation takes priority over all distribution shape signals.
- **Bimodal** — the column's distribution has two distinct peaks, detected by a compound three-gate test (all three must pass): (1) Hartigan's Dip Test (`p < bimodal_dip_p_value_threshold`); (2) component separation via Ashman's D (`cluster_separation > bimodal_separation_threshold`, default 2.0); and (3) minimum component weight (`minority_weight > bimodal_minority_weight_threshold`, default 0.05). When set, `NumericStats.bimodal_stats` is populated with `BimodalStats`. Routes to the Bimodal Imputation Framework in Phase 2. Mutually exclusive with `NearConstant` (a 90%-mode column cannot be bimodal). See ADR-0031, ADR-0032, ADR-0042.
- **HighOutlierDensity** — the fraction of values beyond `outlier_sigma_threshold` standard deviations from the mean exceeds `high_outlier_density_threshold` (default 0.05). Stored as `NumericStats.outlier_density`. An independent escalation trigger in Phase 2's Priority 7 distribution shape condition, alongside `KurtosisTag.Leptokurtic`. See ADR-0033.

## BimodalStats

A dataclass stored as `NumericStats.bimodal_stats`. Present (non-`None`) when and only when `NumericFlag.Bimodal` is set; `None` for all other columns. Contains:

- **`dip_statistic`** — the raw dip statistic from Hartigan's Dip Test
- **`dip_p_value`** — the p-value from Hartigan's Dip Test; the detection threshold is `NumericProfileConfig.bimodal_dip_p_value_threshold`
- **`center1`**, **`center2`** — the two cluster means from the 2-component GMM fitted after the dip test fires. Used by the Bimodal Imputation Framework for cluster-conditional fill assignment and domain-constrained GMM Sampling.
- **`cluster_separation`** — Ashman's D separation score between the two GMM components.
- **`minority_weight`** — the weight of the smaller component from the 2-component GMM (range `[0, 0.5]`).

The invariant is bidirectional: `NumericFlag.Bimodal` present ↔ `bimodal_stats` is not `None`. Part of the Phase 1 output; consumed by Phase 2 without re-computation. See ADR-0042.
  _Avoid_: GMM stats, bimodal metadata

## SemanticType

The ML-level interpretation assigned to a column by the type detector. One of:

- **Numeric** — a continuous or discrete quantitative variable. Profiled with descriptive statistics, histogram, percentiles.
- **Categorical** — a fixed-vocabulary string or integer label. Low cardinality, suitable for one-hot or ordinal encoding. Profiled with frequency distribution.
- **Text** — a natural-language string column. Values are multi-token, near-unique, and not fixed-vocabulary (names, descriptions, addresses). Excluded from correlation matrices; routed to the text profiler.
- **Boolean** — a binary column (native `pl.Boolean`, integer `{0,1}`, or string `{"true","false","yes","no"}`).
- **Datetime** — a temporal column (native date/datetime dtype, coerced from string, or from a numeric epoch with a declared unit). String coercion normally relies on Polars format inference; when inference cannot guess a format (e.g. bare years like `"2015"`), the caller declares one per column via `ProfileConfig.datetime_.set_datetime_format(column, format)` (stored in `datetime_formats`). A declared format is applied with `strict=False`: rows that don't match become null (surfacing as **Format Mismatch** if any non-missing value fails), and only a column where *no* value parses raises `OverrideCoercionError`.
- **Identifier** — a unique key column with no statistical signal (UUIDs, codes, sequential indices). Stats are skipped entirely.

### Text vs Categorical

A string column is **Text** when its values are natural-language content — names, descriptions, addresses, free-form input — where each value is unique or near-unique and contains multiple tokens. **Categorical** strings are low-cardinality, fixed-vocabulary values where the set of labels is small and meaningful (e.g. `"S"`, `"C"`, `"Q"` for embarkation port).

The distinction matters for ML: Categorical columns go through frequency profiling and enter the correlation matrix (Cramér's V); Text columns do not — encoding a `Name` column as one-hot produces noise, not signal.

## Effective Null

A value that counts as missing beyond a standard Polars `null`. Detection combines dtype-driven automatic rules and user-declared sentinels:

- **String / Utf8 columns** — standard null + empty/whitespace-only string (always, unconditional) + string sentinel matching (see **String sentinel** below).
- **Float32 / Float64 columns** — standard null + `NaN` + `Inf`.
- **Numeric sentinel** — a user-declared value (e.g. `-999`, `9999`) for a specific column, treated as effective null for that column only. Declared per-column in `ProfileConfig.numeric_sentinels`; surfaced in `StructuralProfileResult` so Phase 2 can apply the same rules without a config reference. Not auto-detected. Applies to any numeric dtype. User declarations supplement automatic float rules.
- **String sentinel** — for String/Utf8 columns, sentinel string matching follows replace semantics: if the user has declared `ProfileConfig.string_sentinels` for a column, only those values are checked (case-insensitive); if no declaration exists, the hardcoded defaults (`"NA"`, `"NAN"`, `"NULL"`, `"NONE"`, `"?"`) apply. Empty/whitespace-only strings are always effective null regardless of declarations. Replace semantics exist because string null encoding is domain-specific with no universal standard — a user who knows their domain well enough to declare sentinels also knows better than the library what counts as null, and the hardcoded set should not be silently imposed on top of their declaration.
- **All other dtypes** — standard null only (unless a numeric sentinel is declared).

## Format Mismatch

A column-level signal that a column contains values that are **present but uninterpretable** under the coercion for its semantic type — distinct from an **Effective Null**, which is *absent*. Fires for any coercing profiler (`Numeric`, `Boolean`, `Datetime`) whenever at least one value that is neither a genuine null nor an **Effective Null** fails to coerce (e.g. `"banana"` in a numeric column, `"maybe"` in a boolean column, `"12/2015"` in a datetime column parsed as `%Y-%m-%d`). Recognized missing-markers — empty/whitespace strings and declared/default string sentinels like `"NA"` — are *missing*, not dirty, and never trip the flag; the orchestrator resolves string Effective Nulls to genuine nulls before the typed profiling pass so the pure sub-processors need no config to honour this.

Deliberately a **boolean flag with no count**: it raises a hand — "this column is not clean" — without quantifying how many values are dirty. For the purpose of computing statistics, an uncoercible value is unusable and is treated exactly like a null (dropped); Format Mismatch does not repartition or adjust the null ratio, and the null-based signals (e.g. MNAR) are computed unchanged. A column may therefore carry both a missingness signal and Format Mismatch simultaneously, which a caller reads as "some of what looks missing here is actually dirty data." The library never guesses formats, counts mismatches, locates them, or repairs them. See ADR-0043.
  _Avoid_: parse failure, bad value, malformed null, format_mismatch_count

## TypeFlag

An annotation attached to a `ColumnProfile` during type detection. Splits into two categories with different roles:

- **Decision flags** — drive the `SemanticType` verdict directly; the type detector branches on their presence before assigning `semantic_type`. Includes `encoded_category`, `identifier_column`, `boolean_candidate`, `free_text_candidate`.
  - `encoded_category` — an integer column reclassified from `Numeric` to `Categorical` because it looks like a coded category rather than a measurable quantity. Fires when either: (a) cardinality is low relative to row count (`n_unique < encoded_category_max_unique` **and** `n_unique / n_valid < encoded_category_max_ratio`), or (b) the values form a tight sequential run (`range_span == n_unique`, e.g. consecutive years) **and** `n_unique` is under a wider absolute limit (50, vs. the normal `encoded_category_max_unique`). `encoded_category` and `identifier_column` are mutually exclusive — low-cardinality and near-unique cannot both be true, so the detector checks `encoded_category` first and only evaluates `identifier_column` if it didn't fire. A narrow-range integer column like `Year` (e.g. 2000–2010) typically triggers this via the tight-sequence path and is classified `Categorical`, not `Numeric` or `Datetime` — there is no automatic int→Datetime inference (see **Datetime**).
- **Annotation-only flags** — attached after `semantic_type` is already decided; purely descriptive, read-only metadata in the output JSON. Includes `numeric_coerced` (string column successfully cast to float), `user_override` (the semantic type was explicitly set by the caller via `set_column_type` — the detector's verdict was ignored for this column), `numeric_kind_override` (the `NumericKind` was explicitly set by the caller via `PipelineConfig.numeric_kind_overrides` — distinct from `user_override`, which is SemanticType-only; both flags can coexist on the same column when the user overrides both).

## Phase 2 — Imputation

### Missingness Mechanism

The causal reason why values are missing in a column. Determines which imputation strategy is appropriate.

- **MCAR** (Missing Completely At Random) — missingness is unrelated to any observed or unobserved value. No `MARSuspect` flag from Phase 1 and not declared MNAR. Simple imputation (Mean, Median, Mode) is valid.
- **MAR** (Missing At Random) — missingness is correlated with other observed columns. Detected in Phase 1 via `MissingnessFlag.MARSuspect` (missingness indicator Pearson correlation exceeds `ProfileConfig.missingness.mar_correlation_threshold` — configurable, default 0.6 — with any other active column, regardless of that column's semantic type). Missingness correlations are computed across all column types; a numeric column's missingness may correlate with a categorical column's missingness and still qualify as `MARSuspect`. Model-based imputation (MICE, KNN) is appropriate when numeric predictors are available; if `NonlinearityTag.Unpredictable` fires, the column falls back to Median regardless.
- **MNAR** (Missing Not At Random) — missingness is caused by the unobserved value itself. Cannot be detected from data alone. Declared explicitly by the user via `ImputationConfig.mnar_columns`. Handled with a data-derived fill (observed mean when `SkewSeverity.Normal`, observed median otherwise — computed from non-missing rows only) and a binary missingness indicator. The fill centres the missing rows within the observed distribution rather than placing them at an arbitrary sentinel, minimising directional bias for linear and distance-based downstream models while preserving the indicator as the primary MNAR signal. Phase 2 output remains null-free. **Exception (`NumericKind.BoundedDiscrete`):** when the MNAR column is BoundedDiscrete, the fill is Mode (not mean/median) — domain membership must be guaranteed; the missingness indicator is still added.
  _Avoid_: non-random missing, structurally missing

### Imputation Strategy

The method applied to fill missing values in a column. Selected by `decide()` based on SemanticType, missingness mechanism, severity, distribution shape, and dataset size. One of:

- **Mean** — fill with column mean. Applied to `SemanticType.Numeric` MCAR columns with `SkewSeverity.Normal`, `MissingSeverity.Minor`, and `KurtosisTag` not `Leptokurtic`. A `Leptokurtic` column escalates to KNN even at Minor severity because heavy tails make the mean an unreliable central-tendency estimate for missing rows.
- **Median** — fill with column median. The scalar fallback after distribution shape escalation is not triggered or model-based size guards are not met. Applied to: MCAR `Minor` with skew present but `KurtosisTag` not `Leptokurtic`; MCAR `Moderate` without Leptokurtic or `SkewSeverity.Severe`; MAR `Minor`/`Moderate` without distribution shape escalation; any severity or mechanism when `NonlinearityTag.Unpredictable` fires; any severity when `NumericFlag.NearConstant` is present (de-escalation cap — model-based is wasted when 90%+ of values share the mode). Also the terminal fallback when all model-based size guards fail.
- **Mode** — fill with most frequent value. Applied to `NumericKind.BoundedDiscrete` columns and `SemanticType.Categorical` / `SemanticType.Boolean` columns. For BoundedDiscrete columns, Mode is the scalar fill for **all** routing outcomes inside the BoundedDiscrete gate — including MNAR (fill only; the MNAR strategy and its missingness indicator are preserved), all MCAR severity paths where model-based strategies are not attempted, and all runtime model-based fallbacks. Mean and Median are never used as scalar fills for BoundedDiscrete.
- **KNN** — fill using k-nearest neighbour rows. Applied in three routing contexts: (1) `MARSuspect` columns where MICE is disqualified by the `mice_min_rows` floor; (2) `MissingSeverity.High` MCAR columns, subject to size guards; (3) Distribution shape escalation — any MCAR or MAR column at `Minor` or `Moderate` severity where `KurtosisTag.Leptokurtic` OR `SkewSeverity.Severe` is present, subject to size guards. Not applied when `NonlinearityTag.Unpredictable` is present (pre-routing guard) or when `NumericFlag.NearConstant` is present (de-escalation cap). Falls back to MICE if size guards are exceeded; falls back to Median if all size guards fail. `n_neighbors` is computed dynamically at Phase 2 fit time from three signals via a multiplicative formula: `n_features` (dimensionality raises k), feature matrix missingness fraction (high missingness raises k), and complete row fraction (low completeness raises k); bounded by `knn_min_neighbors` and `knn_max_neighbors` in `NumericImputationConfig`. `weights` is `"distance"` when distances are reliable (`miss_frac < knn_distance_weight_max_null_ratio` AND `n_features ≤ knn_distance_weight_max_features`); otherwise `"uniform"`. Feature columns are NaN-safe scaled (nanmean/nanstd from `train_df`) before fit; imputed values are inverse-scaled. Stored as `_FittedKNN(model, col_means, col_stds)` — the fitted unit of the single `"knn"` block, reachable through `FittedImputer.units`. The chosen `n_neighbors`, `weights`, and scaling status are reported on `FitSignals`.
- **MICE** — the **single unified chained-equations strategy**: one `IterativeImputer` fit over the **full active-numeric matrix**, writing back only the MICE-owned columns. Absorbed the former `Regression` strategy (removed by ADR-0079), which built the identical `IterativeImputer` and differed only in feeding one target *all* active-numeric predictors and keeping one column — a distinction measurement found made no accuracy difference (≤0.05% RMSE, no consistent direction, #405). There is **no predictor-breadth dial** (full active-numeric breadth is the only mode; block-only predictors were a measured strict loss, +74–93% RMSE) and **no joint-vs-single dial** (always one joint block; one-at-a-time is an accuracy tie at ~4–5× cost) — #408. Applied whenever a numeric column routes to model-based chained imputation: `MARSuspect` + `MissingSeverity.Severe`, multiple columns simultaneously `MARSuspect`, `MARSuspect` + `MissingSeverity.High` with correlated predictors (the former Regression trigger, now a provenance string only), or `MissingSeverity.Severe` on any MCAR column (20–50% missing). All such columns join **one joint block** — no partition, no block-size cap. Subject to the `mice_min_rows` floor (renamed from `regression_min_rows`), applied **uniformly** to every entry path including `multi_mar`/`Severe`: a column below the floor diverts to KNN→Median rather than entering a chained fit on too few rows (a deliberate tiny-*n* behaviour change). The internal estimator is auto-selected by taking the most complex `NonlinearityTag` across all MICE columns and passing it to `RegressionEstimatorFactory`. If all MICE columns are `Unpredictable`, the block is skipped and each column falls back to Median individually. `max_iter` and `tol` are computed dynamically from seven data signals with conservative aggregation across MICE columns: most-complex `NonlinearityTag`, feature matrix missingness fraction, minimum R²_linear across MICE columns, maximum pairwise Pearson `|r|` among MICE columns (from `CorrelationProfiler`), complete row fraction, minimum IQR across MICE columns for scale-relative `tol`, and `ComplexNonlinear` tol tightening. `initial_strategy` is `"median"` if any MICE column has `SkewSeverity >= Moderate`; otherwise `"mean"`. `imputation_order` stays at the sklearn default `"ascending"` (fewest-missing first — this is already the better-grounded order). `n_nearest_features` is the **sole scale governor** (there is no block-size cap): set only when the block exceeds `mice_n_nearest_features_min_cols` columns, counted over the **full active-numeric breadth** (not just the MICE columns), value the median informative count with `|Pearson r| > mice_correlation_threshold`, capped at `mice_max_nearest_features`. A column is never severed to a cheaper strategy to keep the block small. Predictor relevance is derived from `CorrelationProfiler` value-level correlations, not from missingness `correlated_with`. `sample_posterior` stays `False`; posterior sampling is deferred to a future multiple-imputation scope. **Train/serve frame:** the block's inputs are a strict superset of its targets, so it fits on the raw train split and serves off ADR-0070's shared pre-model snapshot (train ≠ serve, inherited from the former Regression unit). The **scalar-half train/serve skew is closed uniformly** (ADR-0079, #411): the block fits on the same scalar-filled frame it serves on — killing a +71–107% RMSE regression for linear estimators — reproducing the scalar-owned predictors' central tendency inline off the plan's decided tendency rather than consuming sibling scalar units (keeping `fit_unit` standalone and the ADR-0056/0061/0071 independence invariants intact). Not gated on estimator family. Convergence (`n_iter_ == max_iter`) and the chosen estimator are reported once on the `"mice"` unit's `FitSignals`, not per column. See ADR-0079 (collapse), ADR-0011 (estimator selection), ADR-0062 (data-dependent hyperparameters).
- **MNAR** (strategy) — fill with the observed mean (`SkewSeverity.Normal`) or observed median (any other severity) computed from the non-missing rows of the MNAR column. Always adds a binary missingness indicator (`{col}_missing`). Applied exclusively to declared MNAR columns. The skew severity that drove the choice is part of the decide-time rationale in `ColumnImputationRecord.signals`; the computed fill value is a fit-time fact, reported in `FitSignals.notes`. Serialised as `"mnar"`. No user-configurable fill override — the fill is always data-derived.
  _Avoid_: imputation method, fill strategy, constant fill
- **GMM Sampling** — fill by drawing values from the fitted 2-component Gaussian Mixture Model stored in `BimodalStats`. Does not predict from features — it samples from the column's known distribution shape. Applied to `NumericFlag.Bimodal` columns with no correlated features (branch 4 of the Bimodal Imputation Framework), regardless of `NonlinearityTag` — it makes no R² claim and is not subject to the Unpredictable guard. Not applied to `NumericKind.BoundedDiscrete` columns: branch 4 routes to Mode for discrete domains (sampling a continuous GMM into a finite domain is semantically inappropriate). Preserves the bimodal marginal distribution in the imputed output. Requires `PipelineConfig.random_seed` for determinism. See ADR-0032.
  _Avoid_: GMM imputation, mixture sampling
- **Cluster-Conditional Imputation** — fill by assigning each missing row to one of the two distribution clusters identified by the Bimodal Imputation Framework, then filling with the cluster-appropriate statistic. Cluster assignment uses (in order of availability) the declared grouping variable, feature-centroid nearest-neighbour assignment, or GMM posterior. For continuous bimodal columns, the fill is the cluster mean or median (skew-driven). For `NumericKind.BoundedDiscrete` bimodal columns, the fill is always the cluster mode — preserving the finite domain. See ADR-0032.
  _Avoid_: cluster fill, bimodal fill
- **Indicator** — not a fill strategy. Assigned to `{col}_missing` columns that `transform()` produces when `indicator_added=True` for the source column. Written into `self.records` at fit time so the full output schema is inspectable before `transform()` runs. Carries `SemanticType.Boolean`. See ADR 0025.

### Missingness Indicator

A binary feature column (`column_missing = 1` if value was missing, else `0`) appended to the DataFrame alongside imputation. Always added for MNAR columns. Optionally added for any other column declared in `ImputationConfig.add_indicator_columns`. Each indicator column gets a `ColumnImputationRecord` with `ImputationStrategy.Indicator` and `SemanticType.Boolean` written into `self.records` at fit time (see ADR 0025). `apply_exclusions(config)` registers indicator columns as Soft Exclusions for Phases 3–6 so downstream phases skip them automatically.
  _Avoid_: missing flag column, null indicator

### ImputationResult

The output of Phase 2. Contains:
1. The imputed `pl.DataFrame` with all effective nulls filled and any missingness indicator columns appended.
2. A per-column audit log `dict[str, ColumnImputationRecord]` recording the strategy used, fill value (for scalar strategies), whether an indicator was added, and the signals that drove the decision (severity, mechanism, size guards triggered, etc.). Fit-time facts such as convergence are **not** here — they live on the `FitSignals` returned by the fit that produced the unit.
3. `dropped_columns` — column names removed because their `DropCandidate` flag fired (>50% effective missing). These columns are absent from the returned `dataframe`.
  _Avoid_: imputation output, filled dataset

### Numeric Imputation Decision Priority

For `SemanticType.Numeric` columns, `decide()` applies the following priority order (first match wins):

1. `DropCandidate` flag (`>50%` missing) → drop column entirely
1.5. **`per_column_constant_fill` / `per_column_strategy` override** — checked in order: (a) if the column is present in `NumericImputationConfig.per_column_constant_fill`, routes to `ImputationStrategy.Constant` and records `"per_column_constant_fill_override: user declared constant fill"` in signals; (b) otherwise, if declared in `per_column_strategy`, use the declared strategy and record `"per_column_strategy_override: user forced strategy=X"`. In both cases all routing priorities below (2–7) are bypassed. For model-based strategies declared in `per_column_strategy` (KNN, MICE), forcing past a routing size threshold is informed consent: the unit trains rather than being blocked, and the oversize/undersize condition is reported via `FitSignals.warnings` and an `ImputationFitWarning` (ADR-0071, ADR-0074 — superseding ADR 0029's fit-time `ValueError`).
2. Declared MNAR → `ImputationStrategy.MNAR` (observed mean/median fill, skew-driven) + missingness indicator. **Exception:** for `NumericKind.BoundedDiscrete` columns the fill is Mode, not mean/median — domain membership is guaranteed; the indicator is still added.
3. **`NumericKind.BoundedDiscrete` gate** — fires before the Unpredictable guard and before MARSuspect routing. Inside the gate the column runs its own full sub-chain and exits; priorities 4–7 are never reached for BoundedDiscrete columns. Sub-chain (first match wins): (a) `NonlinearityTag.Unpredictable` → Mode. (b) `NumericFlag.NearConstant` → Mode. (c) `NumericFlag.Bimodal` → Bimodal Imputation Framework (BoundedDiscrete variant): branch 1 (grouping variable → Cluster-Conditional with cluster mode fill); branch 2 (≥ `bimodal_min_correlated_features` features with `|r| > bimodal_correlation_threshold` → `_mar_strategy(severity=High, multi_mar=False)`; Median terminal replaced by Mode); branch 3 (1 to `bimodal_min_correlated_features − 1` features → Cluster-Conditional with cluster mode fill); branch 4 (no features, or `feature_correlation` is `None` → Mode). When `feature_correlation` is `None`, branches 2 and 3 are skipped. (d) `MARSuspect` → domain-snapped MAR sub-chain (same MICE/KNN fallback order as Priority 5) → Mode terminal. (e) MCAR by severity → domain-snapped MCAR sub-chain (same severity routing as Priority 7) → Mode terminal. **Scalar fill rule**: all scalar fills inside the BoundedDiscrete gate are Mode — Mean and Median are never used. This applies to all severity and mechanism combinations where model-based strategies are not attempted (including Minor + Normal skew MCAR). **Domain-snap**: every model-based prediction (KNN, MICE) is post-processed as `clip(round(prediction), min, max)` using `NumericStats.min` / `NumericStats.max`, enforcing the finite domain. Domain-snap does not apply to Mode fills — Mode is always a valid domain member. Snap bounds are stored in `ColumnImputationRecord.domain_snap_bounds: Optional[tuple[float, float]]` so `transform()` can apply the snap without the profile. There is no **runtime** model-based fallback: size guards are settled at decide-time, and a unit that cannot train raises rather than degrading to a scalar (see **fit_unit**). The Mode-not-Median rule therefore governs decide-time routing only. See ADR-0035 (amends ADR-0018), ADR-0071.
3.5. **`NumericFlag.Bimodal` (Bimodal Imputation Framework)** — applies to non-BoundedDiscrete columns only (BoundedDiscrete handles bimodal inside its gate at Priority 3, step c). Fires before the Unpredictable guard: a bimodal column with no correlated features routes to GMM Sampling regardless of `NonlinearityTag`. Branch evaluation (first match wins): (a) user-declared grouping variable in `bimodal_grouping_variables` → Cluster-Conditional; (b) ≥ `bimodal_min_correlated_features` features with `|r| > bimodal_correlation_threshold` → `_mar_strategy(severity=High, multi_mar=False)`; (c) 1 to `bimodal_min_correlated_features − 1` features → Cluster-Conditional; (d) no features, or `feature_correlation` is `None` → GMM Sampling. When `feature_correlation` is `None`, branches (b) and (c) are skipped; (a) is checked first, then (d). See ADR-0032.
4. **`NonlinearityTag.Unpredictable` (pre-routing guard)** — applies to non-BoundedDiscrete columns only (BoundedDiscrete handles Unpredictable inside its gate at Priority 3). → Median, unconditionally. Overrides MAR mechanism and all severity levels below. Recorded in signals. See ADR-0016.
5. `MARSuspect` → MICE (if Severe or multi-column MAR, or High + `correlated_with` non-empty — the last was the former Regression branch, now emitting MICE) → KNN (if High + no correlations, or Minor/Moderate + `KurtosisTag.Leptokurtic`/`SkewSeverity.Severe`, size-guarded) → Median. The `mice_min_rows` floor applies to every MICE entry here: a below-floor column diverts to KNN→Median.
6. **`NumericFlag.NearConstant` (de-escalation cap)** → Median. Prevents distribution shape escalation; 90%+ values share the mode so model-based is wasteful.
7. MCAR by severity + distribution shape: `TailAsymmetryTag.RightHeavy` or `LeftHeavy` upgrades the effective `SkewSeverity` by one level before evaluation (stored severity unchanged). `Minor` + `SkewSeverity.Normal` + not `Leptokurtic` + not `HighOutlierDensity` → Mean; `Minor`/`Moderate` + (`KurtosisTag.Leptokurtic` OR `SkewSeverity.Severe` OR `NumericFlag.HighOutlierDensity`) → KNN (size-guarded) → Median; `Moderate` otherwise → Median; `High` → KNN → MICE → Median; `Severe` (20–50%) → MICE → KNN → Median. For MCAR routing, value-level Pearson correlations from `CorrelationProfiler` serve as a feature-predictability check: when max `|r| < 0.2` against all available numeric features, model-based strategies are skipped and Median is applied directly. `NumericFlag.Bimodal` columns never reach Priority 7 — they are intercepted at Priority 3.5. See ADR-0017, ADR-0033.

### Bimodal Imputation Framework

A four-branch routing sub-tree applied to any column with `NumericFlag.Bimodal` during Phase 2. For non-BoundedDiscrete columns, fires at **Priority 3.5** (after the BoundedDiscrete gate, before the Unpredictable guard). For BoundedDiscrete columns, fires inside the BoundedDiscrete sub-chain at step (c). Branches are evaluated in order; the first with sufficient evidence wins:

1. **Grouping variable available** — user-declared in `NumericImputationConfig.bimodal_grouping_variables`. Fill with cluster-conditional statistic: mean or median per group (skew-driven) for continuous columns; cluster mode for BoundedDiscrete.
2. **Many correlated features** — `≥ bimodal_min_correlated_features` features with `|r| > bimodal_correlation_threshold`. Delegates to `_mar_strategy(severity=High, multi_mar=False)`: MICE → KNN → Median fallback chain. For BoundedDiscrete columns, Median terminal is replaced by Mode.
3. **Few correlated features** — 1 to `bimodal_min_correlated_features − 1` features with `|r| > bimodal_correlation_threshold`. Cluster-Conditional Imputation: assign missing rows to the nearest cluster centroid (GMM centers + cluster-conditional feature means), fill with cluster mean/median (skew-driven) for continuous; cluster mode for BoundedDiscrete.
4. **No correlated features** — GMM Sampling from the fitted 2-component GMM (non-BoundedDiscrete only). For BoundedDiscrete columns, Mode is used instead — sampling a continuous GMM into a finite discrete domain is semantically inappropriate.

When `feature_correlation` is `None` (correlation profiling not run), branches 2 and 3 are skipped: branch 1 is evaluated first; if no grouping variable, branch 4 applies (GMM Sampling for non-BoundedDiscrete, Mode for BoundedDiscrete).

For continuous bimodal columns where `NonlinearityTag.Linear` is detected, the chained-equations estimator selected for branch 2 is overridden to `RandomForestRegressor` — linear models produce valley predictions for bimodal targets.

Config fields in `NumericImputationConfig`: `bimodal_min_correlated_features: int = 3` (branch 2/3 boundary), `bimodal_correlation_threshold: float = 0.2` (minimum `|r|` to count a feature as correlated for branch counting), `bimodal_grouping_variables: dict[str, str]` (column → grouping column name for branch 1).
  _Avoid_: bimodal strategy, bimodal routing

### Evaluation

The opt-in phase that measures imputation quality, deliberately separated from fitting and triggered on the user's own clock. The imputation fit path learns fill values and models only; it computes no diagnostics. Evaluation is its own orchestrator (`EvaluationOrchestrator`) with its own `observer=`, and is **stateless** — the caller passes the fitted imputer *and* the data back in rather than the `FittedImputer` hoarding the DataFrame, preserving that object's serializable contract. Evaluation answers **two distinct questions** through two methods, split because only one is retrain-free (see ADR-0058, revising ADR-0057):

- **`inspect(fitted_imputer, train_df) -> InspectionReport`** — the cheap "do the filled-in numbers look sensible?" check. Reuses the models `fit_unit` already produced (no retraining, no `profile` needed) by running `FittedImputer.transform` and comparing filled cells against observed values.
- **`score_accuracy(fitted_imputer, train_df, profile) -> AccuracyReport`** — the expensive "how accurate are the filled-in numbers?" check. Honest held-out accuracy is irreducibly a refit (a fitted model scored on cells it trained on is optimistically biased), so this cross-validates on folds — but reuses the strategy decisions already in `fitted_imputer.records` instead of re-routing. Each fold's stand-in model is a **faithful copy of the delivered model M's recipe** (see **Fold Stand-in Fidelity** below): the number is a conservative baseline for M rather than a grade of a fold-tuned variant. Its fold work honours the concurrency (ADR-0056) and Substep-progress (ADR-0055) rules.

Scope is **imputation only** — deterministic phases (encoding, scaling) have no held-out truth to score; the semantic-type registry is the sole extension seam for future imputer column-types. See ADR-0057, ADR-0058.
  _Avoid_: scoring, validation, assessment phase

### InspectionReport / InspectionDiagnostic

The retrain-free result of `EvaluationOrchestrator.inspect`. `InspectionReport` is a per-column mapping (`[col]` / `in` access) of `InspectionDiagnostic`; present for model-based strategies (KNN, MICE, and the bimodal strategies), absent for scalar strategies (Mean, Median, Mode), Passthrough, Dropped, and MNAR. Every field is readable from the already-fitted model applied to `train_df` — nothing is retrained.

- **`converged`** — whether `IterativeImputer` stabilised before reaching `max_iter`; `None` for KNN and scalar strategies.
- **`n_iter`** — actual iteration count of `IterativeImputer`; `None` for KNN and scalar strategies.
- **`n_neighbors_used`** — actual `n_neighbors` used by the KNN block; `None` for MICE and scalar strategies.
- **`k_capped`** — `True` when the adaptive k formula exceeded `n_rows − 1` and was forced to that bound (data-size cap), signalling the model is averaging nearly all rows; `False` when within bounds; `None` when `knn_n_neighbors` override is active (user chose k deliberately) or strategy is not KNN.
- **`imputed_mean`**, **`imputed_std`** — distribution of values imputed for the null rows in `train_df`.
- **`observed_mean`**, **`observed_std`** — distribution of non-null values in `train_df`.
- **`variance_ratio`** — `imputed_std / observed_std`; low values indicate distribution collapse (the model is predicting near-constant values for all null rows).

Part of the Public API.
  _Avoid_: fit diagnostic, quality score

### AccuracyReport / AccuracyDiagnostic

The refit-based result of `EvaluationOrchestrator.score_accuracy`. `AccuracyReport` is a per-column mapping of `AccuracyDiagnostic`, present for the same model-based strategies as `InspectionReport`. Each field is a held-out (cross-validated) accuracy measure — the model is *refit without* the scored cells, so the numbers are honest rather than in-sample.

- **`r2_cv`** — mean cross-validated R² across `refit_r2_cv_folds` (default 5) folds on complete rows; `None` when fewer than `refit_r2_min_complete_rows` (default 50) complete rows are available. k-fold rather than a single holdout reduces variance when complete rows are few. (Formerly `r2_train`, renamed because it was never a train score.)
- **`rmse`** — root-mean-square error of imputed vs. true values on the same held-out rows used for `r2_cv`; `None` under the same guard. Diagnostic-only — in column-specific units, no universal threshold.
- **`mae`** — mean absolute error on the same held-out rows; `None` under the same guard. Diagnostic-only for the same reason as `rmse`.

For MICE, these are computed per column via k-fold CV on the intersection of complete rows across **all** MICE columns: in each fold, each column's target is masked independently and evaluated from the shared throwaway MICE model for that fold. If that intersection is smaller than `refit_r2_min_complete_rows`, all fields are `None` for every column in the block. Part of the Public API.
  _Avoid_: fit diagnostic, quality score

### Fold Stand-in Fidelity

The rule governing how a `score_accuracy` fold model must resemble the delivered model M. Held-out accuracy cannot be measured on M itself (M trained on every complete cell, so scoring it in-sample is optimistically biased) — it is measured on a **fold stand-in**: the same recipe fit on a fold's training rows, whose score is a conservative baseline for M (more data is expected to make M at least as good). Fidelity splits every model into two parts treated oppositely inside the fold loop:

- **Recipe** — configuration/hyperparameters chosen before seeing the answers (estimator type, regularization, `max_iter`, `tol`, `n_neighbors`, `weights`, feature set). **Frozen from M** so the stand-in differs from M only in training on fewer rows.
- **Learned parameters** — everything M fit from the data (regression coefficients, KNN scaling `col_means`/`col_stds`, MICE fills, centroids). **Re-learned on each fold's training rows only.** Freezing these would leak the held-out cells back in (they were computed from all rows, including the validation fold) and restore the in-sample bias CV exists to remove.

MICE is the template (freezes estimator/`max_iter`/`tol`, refits per fold); ex-`Regression` columns score through this same MICE path (ADR-0079 removed the separate `FittedRegression` fold arm and `_score_regression_cv`). KNN freezes M's `n_neighbors`/`weights` but recomputes feature scaling per fold's training rows. See ADR-0059 (refines ADR-0058).
  _Avoid_: surrogate model, twin model, refit replica

### Per-Column Imputation Override

An explicit assignment for a named column in `NumericImputationConfig` that bypasses the computed or dynamically-derived value. Applied at decide-time, so an override is visible in the plan before anything trains. Distinct from a **Hyperparameter Override**, which edits an already-decided plan rather than the config that produced it. Five override types:

- **`per_column_strategy`** — forces a specific `ImputationStrategy`, bypassing all routing priorities 2–7 (MNAR through MCAR). Fires at Priority 1.5 — after `DropCandidate` (which remains a hard gate) but before MNAR routing. Valid strategies: `Mean`, `Median`, `Mode`, `KNN`, `MICE` (`Regression` removed by ADR-0079 — a forced `Regression` config hard-fails). `Constant`, `Passthrough`, `Indicator`, `MNAR`, and `Dropped` raise `ValueError` at construction (`Constant` with redirect to `per_column_constant_fill`). A column in both `mnar_columns` and `per_column_strategy` raises `ValueError` at construction. For model-based strategies, forcing past a routing size threshold is not blocked: the unit trains, and the condition is warned via `FitSignals.warnings` / `ImputationFitWarning` (ADR-0071, ADR-0074 — superseding ADR 0029's fit-time `ValueError`). See ADR 0029 for the Priority 1.5 ordering, which stands.
- **`per_column_constant_fill`** — self-sufficient constant fill declarations. Each column listed here is routed to `ImputationStrategy.Constant` at Priority 1.5, bypassing all routing priorities 2–7. No companion entry in `per_column_strategy` is required or allowed — the presence of a column in this dict fully encodes the intent. Set manually by the user.
- **`mice_max_iter`** — overrides the dynamically computed `max_iter` for the MICE block. Scalar (`Optional[int]`): all MICE columns share one `IterativeImputer`, so a single value governs the entire block. Set manually. See ADR-0037. (The former per-column `per_column_max_iter` override is removed by ADR-0079 — with one joint block there are no per-column `IterativeImputer`s to tune.)
- **`knn_n_neighbors`** — overrides the adaptively computed `n_neighbors` for the KNN block. Scalar (`Optional[int]`): all KNN columns share one `KNNImputer`, so a single value governs the entire block. When set, `k_capped` on `InspectionDiagnostic` is `None` (the adaptive formula was bypassed). Set manually. See ADR-0037.

All override fields are set manually by the user. `per_column_constant_fill` is the only way to route a column to constant fill.
  _Avoid_: column parameter override, per-column config

## Strategy Routing vs Parameter Estimation

Two distinct responsibilities, now split across the two layers of the imputation door — Strategy Routing is `decide()`'s whole job, and Parameter Estimation is `fit_unit()`'s:

- **Strategy Routing** — selecting the imputation method for each column. Uses signals from the `StructuralProfileResult` (computed on the full dataset): `MissingSeverity`, `MissingnessFlag.MARSuspect`, `NumericKind`, `SkewSeverity`, `KurtosisTag`, `TailAsymmetryTag` (severity upgrade), `NonlinearityTag` (pre-routing guard), `NumericFlag.NearConstant` (de-escalation cap), `NumericFlag.Bimodal` (Bimodal Imputation Framework), `NumericFlag.HighOutlierDensity` (independent escalation trigger), and value-level Pearson correlations from `CorrelationProfiler` (feature-predictability check for MCAR routing and bimodal feature-count branching). Routing decisions do not embed any values from the test set into the training process — they are method-selection decisions only.
- **Parameter Estimation** — learning the actual fill values and models. Uses only `train_df`: computes medians, modes, fits KNN / MICE models. The test set is completely invisible during this step.

This distinction is why the two layers take different inputs: `decide(profile, n_rows, config)` sees the profile and never a DataFrame (the profile informs routing — the best full-dataset description of each column's distribution), while `fit_unit(decision, unit_id, df)` takes `train_df` and estimates from it alone (the only data a model is allowed to see). The split makes the leakage boundary structural rather than a matter of discipline: a decision layer that cannot read values cannot leak them. Using full-dataset profile statistics for routing is not data leakage — no test-set values appear in the fitted parameters. Whether that profile *is* full-dataset or train-only is a **Split-Profiling Topology** choice, not a config flag — see below.
  _Avoid_: strategy selection, fill learning

## Split-Profiling Topology

The order in which a user composes profiling and splitting, which determines whether **Strategy Routing** sees full-dataset or train-only statistics. `decide()` is agnostic to a profile's provenance — it routes off whatever `StructuralProfileResult` it is handed — so the routing-leakage stance is expressed by *pipeline shape*, never by an imputation config field. Two canonical topologies:

- **Profile-first** — `StructuralProfiler.profile(full_df)` → `profile_stratified_split(profile)` → `fit(train_df, profile)`. The full-dataset profile is **mandatory**: the leakage-guarded stratified split is driven by it and must run before any train partition exists. Routing reuses that same full profile — intrinsic to this topology, not a decision, and near-identical to train-only routing because the stratified split makes train distributionally representative of full. This is the smart-splitter path.
- **Split-first** — a profile-unaware splitter (`random_split`, `time_split`, `kfold`, and future group / walk-forward / repeated CV) → `StructuralProfiler.profile(train_df)` → `fit(train_df, train_profile)`. Routing sees train only, so it is leakage-clean with no second profiling pass. This is the plain-splitter path, and every new plain-tier CV strategy enables it for free.

A user who wants a smart stratified split *and* train-only routing composes the hybrid explicitly (full-profile split, then re-profile train, then `fit` with the train profile) — a valid two-pass choice the library neither forces nor forbids. See ADR-0051.
  _Avoid_: routing profile flag, leakage mode

## ImputationDecision

The pure, data-free imputation plan produced from `(profile, shape, config)` alone — where `shape = (n_rows, n_features, column set)` — with no access to `train_df`. `n_rows` is a **required input** to `decide()`, not derived from the profile, and callers pass the *train* row count so size guards evaluate against the shape execution will actually face (ADR-0066); `n_features` and the column set stay derivable from the profile, since splitting is row-wise. The plan is computed over the Imputation-phase **active columns** only (the **Phase Active-Columns Contract**): hard-excluded columns are omitted entirely, Imputation-soft-excluded columns appear as `Passthrough` with an exclusion signal, and excluded columns are banned as predictors — block membership, feature counts, and hyperparameter signals see the active set only. Contradictory config (an excluded column also named in `mnar_columns`, `per_column_strategy`, `per_column_constant_fill`, or the indicator declarations) raises `ValueError` at decide-time. See ADR-0077. It is the reification of the **Strategy Routing** half of the routing/estimation split as an inspectable, editable object, and the keystone the execution and persistence layers consume (see the Decision/Execution split, ADR-0060). Distinct from `ImputationResult` (the executed output) and `FittedImputer` (the fitted models): the decision carries the *policy*, never the learned *value* or the fitted model.

- **Value-free by construction** — the decision holds no value learned by the execution layer from `train_df` (no fill values, no fitted coefficients). It *may* hold profile-provided descriptors, including `min`/`max` as `domain_snap_bounds`, because those arrive through the same sanctioned profile channel as every other routing signal. Provenance (full-dataset vs train-only) is governed by **Split-Profiling Topology** (ADR-0051); the decision introduces no new leakage surface. Model training happens only in the execution layer, on `train_df`.
- **Immutable** — edits return a *new* `ImputationDecision` (`with_strategy`, `with_model_choice`, `with_hyperparameters`); nothing is mutated in place, so a stale unit list is structurally impossible and every plan that exists is valid by construction. Edit-time validates *legality* (a declarable strategy legal for the column's semantic type — the output-only labels `Dropped`/`Passthrough`/`Indicator`/`MNAR`/`Constant`/`ClusterConditional`/`GMMSampling` are rejected as in `NumericImputationConfig.set_per_column_strategy`); *data-size feasibility* (size guards) is deferred to execution.
- **Fields** — `column_decisions` (editable per-column map), `units` (materialized execution grouping), `decided_for_shape`, `config_snapshot`, `profile_provenance`, `decided_hyperparameters` / `override_hyperparameters` (the two-map **Hyperparameter Override** storage — see below), `numeric_sentinels` / `string_sentinels` (the declared sentinel maps copied off the profile at decide-time, so the execution layer can normalise effective nulls from the plan alone — the same "a plan loaded from the store must not need the original profile" argument that puts `forced` on the column decision; ADR-0068), and `dropped_columns` (convenience projection of the per-column `drop` flags). `decided_for_shape[0]` and `profile_provenance["row_count"]` are **different facts and never share a value**: the former is the row count the plan was decided for (the train count), the latter the full-dataset count describing the profile. Their differing is the honest record — "decided for 480 rows, from a profile of 600" (ADR-0066). Serialization of the snapshot fields is owned by the envelope format (ADR-0072), not by the object spec; there is no hashing or identity scheme over them any more (see **Persistence**).
- **Produced by an assembler over `route()`** — `_StrategyRouter.route()` stays the routing kernel returning `(strategy, signals)` and is reused as-is; a decision assembler adds `model_choice`, `domain_snap_bounds`, the indicator/mnar/drop flags, derives the `units`, and captures provenance.
  _Avoid_: imputation plan object, routing result, decision record

### ColumnImputationDecision

The pure per-column entry inside `ImputationDecision.column_decisions`. Fields: `column`, `semantic_type`, `strategy`, `signals` (the routing rationale — the "why"), `model_choice` (the concrete estimator family for MICE, resolved at decide-time from `NonlinearityTag` + `n_rows` + `config`; `None` for other strategies), `domain_snap_bounds` (profile `(min, max)` clip bounds for `NumericKind.BoundedDiscrete`; `None` otherwise), `indicator_flag`, `mnar`, `drop`, `forced` (whether the strategy was user-declared rather than routed — written by both producers, the router from `config.per_column_strategy` and the plan-edit path `with_strategy`; a real field, never a parseable signal string, so a plan loaded from the store knows what was forced without the original config object — ADR-0066). `ColumnImputationRecord` composes this type — a record is *decision + `fill_value` + fit metadata* — so the pure plan and the learned values never share a field.
  _Avoid_: column decision record, per-column plan

### ImputationUnit

A unit of execution enumerated in `ImputationDecision.units` — the indivisible chunk `fit_unit` trains and the granularity a user schedules against. The joint MICE block is one unit and the joint KNN block is one unit (their columns train together in a single model call and cannot be split); every independent-strategy column (GMM-Sampling, Cluster-Conditional, scalar) is its own unit. (There is no longer a per-column Regression unit — those columns join the single `"mice"` block; ADR-0079.) Fields: `unit_id`, `strategy`, `columns`, `hyperparameters` (the merged decided-base-plus-override tuple the fitter hands to sklearn — see **Hyperparameter Override**), and `is_block` — whether this unit is a **joint block**, a pure fact derivable from `strategy` alone (membership in `_JOINT_BLOCK_STRATEGIES`) and therefore reconstructed on deserialization rather than trusted from the payload (ADR-0063). `is_block` is deliberately structural only: it says the unit's columns train in one model call, *not* that the unit is expensive and *not* that it can absorb inner parallelism — the latter depends on `model_choice`, which lives on `ColumnImputationDecision` so it is never duplicated onto the unit. **Core Budget** does that cross-referencing instead. (Locked by ADR-0081; lands with the follow-on implementation.) Unit ids are `"mice"` / `"knn"` for the joint blocks (exactly one of each) and `"{strategy}:{column}"` for per-column units — stable across edits, since moving a column into MICE changes the `"mice"` unit's membership but not its id. The unit list is a frozen projection of `column_decisions`, recomputed at every construction.
  _Avoid_: strategy block, fit group, execution chunk

### Hyperparameter Override

A plan edit that replaces named estimator dials on one already-decided unit, applied via `ImputationDecision.with_hyperparameters(unit_id, dict | None)`. Distinct from a **Per-Column Imputation Override**, which is a config field consumed at decide-time: this edits the plan `decide()` already produced, so what the user inspects is exactly what fits.

- **Per-key merge onto an always-complete base** — every dial a strategy resolves is written into `decided_hyperparameters` at decide-time, so the base is complete rather than sparse. An override names only the keys it changes; every other decided dial survives. Successive edits to the same unit accumulate per key, and passing `None` clears that unit's delta back to the decided base.
- **Two maps, one derived value** — the plan stores the complete `decided_hyperparameters` and the sparse `override_hyperparameters` separately; `ImputationUnit.hyperparameters` is the merge, re-derived at every construction. Keeping them apart is what lets a round-tripped plan re-stamp the same units and what makes "what did the library choose vs. what did I change" answerable from the artifact.
- **The base is the schema** — a key absent from the unit's decided base is an unknown key and raises `ValueError` at edit time, naming the unit and the key. There is no separate allowlist to drift from the fitters. Values are not type-checked; an ill-typed value is sklearn's to reject at fit time.
- **Per-unit only** — a joint unit shares one estimator, so a per-column override on `"mice"` or `"knn"` has no meaning and the API does not offer one.

See ADR-0073.
  _Avoid_: hyperparameter config, estimator tuning, plan patch

## fit_unit

The execution layer of the Decision/Execution split — the stateless free function that consumes an immutable `ImputationDecision` and trains exactly one of its `units`. Signature `fit_unit(decision, unit_id, df, random_seed=None, n_jobs_inner=-1) -> UnitFitResult`. Distinct from `ImputationDecision` (the pure plan) and `FittedImputer` (the composed whole-dataframe output): `fit_unit` is the single primitive that turns one into the other, one unit at a time. Deliberately not a one-shot `fit()` and deliberately not an object — **execution owns no state**, so there is no lifecycle to interrupt, no `pending`/`done` bookkeeping, and no resume machinery. Scheduling, retry, and checkpointing are the user's, expressed as ordinary calls in ordinary code. See ADR-0071.

- **`train_df` is a parameter, never held** — nothing survives the call but the returned `UnitFitResult`. Re-running a unit is re-calling the function; "resume" is the user choosing which unit ids to call next. The library persists nothing on its own (see **Persistence**).
- **`df` arrives raw and is normalised inside the call** — every effective null the plan's declared sentinel maps describe becomes a real null before the unit trains, so a sentinel is never fitted as legitimate data (ADR-0068). The maps come off the plan, never a profile, which is what keeps the inputs `(decision, unit_id, df)` and lets a deserialized plan normalise identically. "Already normalised" is deliberately not a precondition: it is indistinguishable from a frame with no sentinels, so it could only be trusted, and normalisation is idempotent — a second pass is a no-op. Per-call normalisation is therefore accepted rather than hoisted behind an `assume_normalized` flag; its scan is trivial next to model training.
- **Failure is single-track: it raises** — size guards are settled at decide-time against the train shape (ADR-0066), so the only fit-time failure left is a genuine fit error, and there is no silent degradation path. `UnitNotTrainableError` carries the structured payload identifying the unit and why it could not train. The earlier two-track scheme (auto-routed strategies degrading to a scalar, forced ones raising, selected by `ImputationConfig.on_fit_error`) is gone along with the executor: forcing a strategy is informed consent, and a plan that cannot train is a fact the user should see rather than a plan the library silently rewrites. Nothing rewrites a decision, so plan-vs-executed divergence no longer exists as a concept.
- **There is no batch wrapper — batch scheduling is user-owned (ADR-0075)** — the former `fit_many` driver is removed. A single global layer switch cannot express the schedule that matters when a batch is dominated by one large RandomForest-routed unit (outer-fan the units with no inner parallelism, then run the inner-capable stragglers one at a time at `n_jobs_inner=-1`); training a whole plan is the caller's own `fit_unit` loop, which can express any such schedule directly.
- **`n_jobs_inner` selects the layer, caller-side** — units are independent at fit time (joint models collapsed inside one unit; routing→fit resolved at decide-time), so a caller's batch parallelizes with order-independent fitted models (ADR-0056). Driving units one at a time via `fit_unit` is an outer degree of one and gets the wide inner parallelism by default (`n_jobs_inner=-1`); a caller who fits units side by side in their own pool asks the library for the number, per unit, via **Core Budget**, otherwise the two layers oversubscribe. The rule is documentation on `fit_unit`, not a guard — informed consent, per ADR-0075. The knob selects *which layer* spends the cores, never how many are spent and never what is computed. The independence rule holds at **both** ends: ADR-0067 briefly narrowed it to a fit-time claim, because the transform chain was a real data dependency between units the rule called independent, but ADR-0070 removed that chain — units now transform off a shared pre-model snapshot and merge on disjoint columns, so "concurrency never changes a result" is true as written again.
- **Core Budget** — the whole-plan answer to "how many cores does each unit want", returned by the free function `core_budget(decision, max_workers, total_cores=None) -> dict[str, int]` mapping `unit_id → n_jobs_inner`. The library owns this **arithmetic**; the pool, the loop, the submission order and the failure policy stay user-owned (ADR-0075 is unamended — this is not a revival of `fit_many`). It is heavy-aware rather than degree-proportional: the `"mice"` block receives `max(1, total_cores − 1_if_knn_present)` and every other unit receives `1`, because a plan holds at most two joint blocks and at most one unit — `"mice"`, and only when its `model_choice` is `RandomForestRegressor` — can consume inner parallelism at all. `max_workers=1` is a sequential drive at outer degree one, so `"mice"` gets `-1`; `max_workers=None` is a pool of unknown degree, not a sequential drive, and takes the parallel branch. A free function and not a property on `ImputationDecision`, because the plan is derived purely from `(profile, shape, config)` and a machine fact hung on it would make the same serialized plan answer differently on a different box (ADR-0072's precedent). The budget is a **snapshot**: a plan edit between computing it and running the loop silently invalidates it, mitigated by placement rather than enforcement. It legitimately returns all ones — with no error and no speedup — when the MICE block routes to `GradientBoostingRegressor` or `BayesianRidge`, neither of which has an `n_jobs`; on default config that is every `ComplexNonlinear` frame above `gradient_boost_min_rows`. This **supersedes** the earlier advice, still live in `fit_unit`'s docstring until the follow-on lands, that a self-parallelised drive must pin `n_jobs_inner=1` on every call — measured at 2352 rows on 12 cores, that pin is a **5.84x regression** against the budget, because it runs a two-unit plan on one core. The budget does not beat a plain sequential loop; it *recovers* it (within 3%). See ADR-0081. (Locked by ADR-0081; lands with the follow-on implementation.)
- **Inner parallelism is spent on fitting, never on prediction** — what makes the `n_jobs` derivation above safe to have. A RandomForest is *not* `n_jobs`-invariant, but the non-invariance is entirely in `predict` (trees are summed in thread-completion order, drifting ~1e-15) and not in `fit` (each tree's seed is drawn sequentially, so forests are byte-identical across the switch). The RandomForest branch of `RegressionEstimatorFactory` is therefore built as a `_CoreInvariantRandomForest`, which fits across `n_jobs` cores and pins itself to one before returning from `fit` — inside `fit`, because `IterativeImputer` predicts during its own round-robin. Left unpinned, a forest is non-deterministic *against itself*: repeated `predict` calls on one fitted model disagree, and `n_jobs` pickles with the estimator, so the artifact never settles (ADR-0069).
- **Model application order is plan order, not completion order** — `FittedImputer.compose` orders `units` by the plan, never by the order threads happen to finish in; composing from thread-completion order makes a parallel fit irreproducible even against itself (ADR-0067). Since ADR-0070 that order no longer reaches the result — it is kept because it is the order a human reads the plan in.
- **Model units transform off a shared pre-model snapshot** — every model-based unit reads the same frame (post-drop, post-indicator, post-scalar-fill) and merges back only its `target_columns`; no unit observes a sibling's output. Each column routes to exactly one strategy and therefore one unit, so targets are **disjoint** and the merge is order-independent *by construction* rather than by convention. Replaces the chain, where each unit consumed its predecessors' output — that shape served every regression model a feature distribution it was never fitted against, and made plan order silently load-bearing on imputation output. The chain's supposed compensation (better-informed features from a sibling's fills) was measured across 30 seeds and found to be a coin flip, ~0.2% and direction-inconsistent, so nothing weighed against the principled shape. Under the ADR-0079 collapse, the unified MICE block is now the `FittedRegression`-shaped unit (inputs ⊃ targets): it reads the **full active-numeric matrix** as predictors and writes back only its `target_columns`, so the scalar-owned columns it does not fill are still read as predictors. The **scalar-half train/serve skew that ADR-0070 left open is now closed** (ADR-0079, #411): the block fits on the same scalar-filled frame it serves on, so a chained model no longer trains on a feature's raw nulls and serves on its median fill. The KNN block still fits over exactly the columns it fills. See ADR-0070 (supersedes the chain half of ADR-0067) and ADR-0079 (closes the scalar half).
- **Observability is a returned record, not an event stream** — `fit_unit` takes no `observer=` and emits no Pipeline Events. A user-orchestrated loop already knows which unit it called and when, so progress reporting for Phase 2 is the caller's; what the library owes back is the per-fit detail the caller cannot see, returned as **FitSignals** on the `UnitFitResult` (ADR-0074). Phase 1 profiling and the Evaluation orchestrator still emit Events as described under **Observability**.
  _Avoid_: imputation runner, fit engine, builder, executor

### FittedUnit

The standalone fitted artifact a single `ImputationUnit` produces once trained — the Tier-1, independently-usable result of the two-tier inference model. A `FittedUnit` can transform *its own columns* on any DataFrame immediately, with no requirement that the rest of the plan be complete: train the MICE chunk, transform those columns, ignore the rest. Each strategy's existing fitted object (`_FittedKNN`, the joint MICE/KNN models, a scalar fill) is a `FittedUnit`. (`FittedRegression` was removed by ADR-0079 — the MICE block, now `FittedRegression`-shaped with inputs ⊃ targets, is the only chained-equations unit type.) Carries the narrower "my own columns are absent" contract; the whole-frame safety errors (`UnseenColumnError`, split-imbalance warnings) live at the Tier-2 aggregate, not here. A `Protocol` rather than a base class: the contract is the `target_columns` property plus `transform`, and each strategy's existing fitted object satisfies it structurally.

The unit carries **no fit metadata at all** — no `executed_strategy`, no `degradation_reason`, no `max_iter_used`, no signals list. Two reasons converged: degradation no longer exists (a unit that cannot train raises, so there is nothing to diverge from the plan), and observability that describes a fit belongs to the fit, not to the artifact that outlives it. Everything a caller wants to know about *how the fit went* is on `FitSignals`, returned alongside the unit and deliberately ephemeral; everything about *what was planned* is already in the plan under the same `unit_id`. Duplicating either onto the unit is how two copies drift (ADR-0066). See ADR-0071, ADR-0074. Every unit's `transform` upholds **Observed-Value Preservation** (below).
  _Avoid_: unit result, partial imputer, fitted chunk

### Observed-Value Preservation

The invariant every `FittedUnit.transform` upholds: **a Fitted Unit fills holes and never edits a value the user supplied.** After `transform`, every cell that was not missing in the input is identical — same value, same dtype. "Missing" means the **Effective Null** predicate (`is_null() OR is_nan() OR is_infinite()` for float columns, `is_null()` alone otherwise), matching exactly what the frame-to-numpy conversion hands the estimator as a hole; a bare `is_null()` would restore a raw `NaN` over a cell the estimator had just correctly filled. Dtype is part of the guarantee, so a fractional fill destined for an integer column rounds rather than widening the column.

Enforced *inside each unit's own `transform`* as its final step (a shared private helper restores observed cells of the unit's `target_columns` only), never in `FittedImputer.transform` — so the guarantee holds on the ADR-0071 stateless door, where a user holds a single Fitted Unit with no `FittedImputer` involved. The domain snap remains a whole-column expression; the terminal correction is the single enforcement point. No opt-out flag exists: the full-configurability rule covers thresholds and strategy knobs, not correctness invariants.

Two boundaries the invariant draws: a strategy that intends to *revise* an observed value (outlier correction, measurement-error repair) can never be a Fitted Unit and would need its own phase; and on the standalone door the unit resolves float `NaN`/`Inf` as missing with no configuration but cannot resolve sentinel-encoded **Effective Nulls** — the declared sentinel maps live on the `ImputationDecision` (ADR-0068), so a caller transforming through a bare unit owns sentinel normalisation. See ADR-0078.
  _Avoid_: value passthrough, no-overwrite rule, mask correction

### UnitFitResult

What `fit_unit` returns: the trained `FittedUnit` bundled with the plan-carried facts that identify it (`unit_id`, `strategy`, `columns`) and the `FitSignals` the fit produced. The bundle exists because the two halves have different lifetimes — the `fitted` half is the durable artifact a user serializes and transforms with; the `signals` half is a record of one fit that is meaningful only next to the call that produced it.
  _Avoid_: fit output, unit bundle

### FitSignals

The structured, ephemeral record of one unit's fit, carried on `UnitFitResult.signals`. Answers "which estimator ran, did it converge, how long did it take" without parsing strings — it replaces the free-text `signals: list[str]` that fitted objects used to accumulate. Fields: `unit_id`, `strategy`, `estimator` (`None` for scalar strategies), `converged` and `n_iter` (`None` outside `IterativeImputer`), `duration_s`, `notes`, and `warnings`.

Deliberately **not persisted and not attached to the fitted unit**: it describes an event, and an event that outlives its call becomes a stale claim about an artifact that may since have been re-fit elsewhere. Anything in `warnings` is additionally raised as an **ImputationFitWarning** through the stdlib `warnings` machinery, so a caller who ignores the record still hears about a non-converged MICE run. See ADR-0074.
  _Avoid_: fit log, diagnostics, signals list

### Two-Tier Imputation Inference

The layering that makes a `FittedImputer` an optional roll-up rather than a precondition for any inference:

- **Tier 1 (unit)** — every trained unit is a `FittedUnit` that transforms its own columns immediately. No completeness required. The unit is the primary artifact.
- **Tier 2 (aggregate)** — `FittedImputer.compose(decision, results)` rolls the trained units into the whole-dataframe `FittedImputer`. Gated on **exact coverage**: every unit in the plan must be present and no extras, so the aggregate cannot silently under-cover the frame. Input is tolerant in shape (a mapping or an iterable of `UnitFitResult`s, in any order) and strict in content. This tier carries the full-schema manifest (ADR-0024) and whole-frame safety (ADR-0026); the untrained dropped/passthrough/indicator records are projected straight from the plan, not trained.

There is deliberately no "partial `FittedImputer` for the columns done so far" — the coverage gate protects the manifest invariant and safe transforms. Progress-so-far is Tier 1: transform with the units you have. See ADR-0071.
  _Avoid_: partial fit, incremental imputer

## Fit/Transform Discipline

The principle that all transforming phases (Phases 2–6) must learn their parameters exclusively from training data and apply those learned parameters to any split — including the test set. Phase 1 (Profiling) is exempt: it is non-transforming and may run on the full dataset without leakage risk.

- **Fit** — the step where a transforming phase reads the training DataFrame and learns all fill parameters (scalar statistics, model weights) for one planned unit. In Phase 2 this is `fit_unit`, and it *only* estimates: strategy selection happened earlier, at decide-time, off the `StructuralProfileResult` and never off the DataFrame (see **Strategy Routing vs Parameter Estimation**). Returns a `UnitFitResult` whose `FittedUnit` is independent of anything that produced it.
- **Transform** — the step where a `FittedImputer` applies its already-learned parameters to any DataFrame (train or test) and returns an `ImputationResult`. Does not re-learn any parameters. Raises `UnfittedColumnError` if the DataFrame contains a column with missing values for which no parameters were learned during fit.
- **FittedImputer** — the stateless output of `FittedImputer.compose()`. Stores the learned strategy and fill parameters per column as a plain data structure. Has no serialization of its own: there is deliberately no aggregate artifact format, because an aggregate is exactly a plan plus its units and both already serialize — a caller persists the `ImputationDecision` and each `FittedUnit`, then rehydrates by calling `compose` again (ADR-0072). `self.records` is a complete manifest of the full train schema: every column present in `train_df` at fit time receives a `ColumnImputationRecord`, regardless of semantic type. Columns with no registered imputer (Text, Identifier, Categorical, Boolean, Datetime) receive `strategy=Passthrough`. Indicator columns (`{col}_missing`) receive `strategy=Indicator`, written at fit time. The invariant is: no record = column was never seen during fit. See ADR 0024 and ADR 0025. `apply_exclusions(config)` propagates all `ImputationStrategy.Dropped` columns into `PipelineConfig` as Hard Exclusions via `add_exclusions`, and registers all `ImputationStrategy.Indicator` columns as Soft Exclusions for Phases 3–6. Nothing records or verifies that the call was made; enforcement is deferred to Phase 3, which will compare the imputer's `Dropped` columns against the config directly. Must be called again per config if phases are chained. See ADR 0023 and ADR 0076.
  _Avoid_: fitted pipeline, trained imputer
- **UnfittedColumnError** — raised by `FittedImputer.transform()` when the input DataFrame contains missing values in a column that had no missing values at fit time (and therefore no strategy was ever selected for it — recorded as `Passthrough`). Signals a split imbalance that must be corrected upstream. Columns that are `Passthrough` *by declaration* — soft-excluded for the Imputation phase, their record carrying the exclusion signal — are exempt: their missing values ride through untouched. See ADR-0077.
- **UnseenColumnError** — raised by `FittedImputer.transform()` at the start of transform, before any fill logic, when the input DataFrame contains a column with no entry in `self.records`. Because `self.records` is a complete train schema manifest (ADR 0024), a missing record unambiguously means the column was never seen during fit. Fires for all unknown columns in a single raise, regardless of whether they have missing values. Distinct from `UnfittedColumnError`: "unfitted" means seen during fit with no missingness; "unseen" means never seen during fit at all. See ADR 0026.
- **FittedColumnAbsentError** — raised by `FittedImputer.transform()` when a column recorded in `self.records` with an active imputation strategy (any strategy other than `Dropped` or `Indicator`) is absent from the input DataFrame. Signals that the test DataFrame has fewer columns than the train DataFrame — always a pipeline bug, not an intentional removal. Distinct from `DroppedColumnAbsentWarning`, which covers columns the library itself decided to drop and where absence is a plausible intentional pre-processing step.
- **DroppedColumnAbsentWarning** — raised by `FittedImputer.transform()` when a column recorded as `ImputationStrategy.Dropped` is already absent from the input DataFrame. Indicates the input was pre-processed outside the library — either intentionally (user removed the column manually) or accidentally (wrong DataFrame passed). Fires once per absent column. Transform proceeds regardless. No library-level suppression mechanism; use Python's standard `warnings.filterwarnings` to suppress if the pre-removal is intentional.

## RowMissingnessDistribution

A dataclass nested inside `MissingnessProfileResult` as the `row_distribution` field. Captures aggregate row-wise missingness statistics — how many columns are simultaneously missing per row across the dataset. Computed by `MissingnessProfiler` in Phase 1.

- **`row_missingness_p90`** — the 90th-percentile count of missing columns per row. A row whose missing-column count exceeds this threshold is considered "globally sparse." Used by `build_label_matrix` to generate the Compound missingness row signal for profile-stratified splitting.

## Profile-Stratified Split

A split mode on `DataSplitter` that consumes a `StructuralProfileResult` and produces a train/test partition whose distributional properties are representative across all signals that downstream phases depend on — not just the target column.

Derived stratification signals (auto-computed from the profile, no user configuration required):

- **Missingness density** — row-level count of columns with missing values; ensures columns with any missingness are proportionally represented in both splits (Phase 2)
- **Extreme value rows** — rows containing values in the tails of numeric distributions; ensures Phase 3 Outlier Detection sees the same extreme-value density in both splits
- **Rare label rows** — rows containing low-frequency categorical labels or rare non-mode values in near-constant columns; ensures Phase 5 Encoding has all labels in both splits

`DataSplitter.profile_stratified_split(profile, test_size)` is the canonical entry point for train/test splits. `DataSplitter.profile_stratified_kfold(profile, k)` is the equivalent for cross-validation. Both use `MultilabelStratifiedShuffleSplit` / `MultilabelStratifiedKFold` from the `iterative-stratification` package. When a target column is declared on `DataSplitter`, it is included in the label matrix automatically so target class proportions and distributional quality are preserved in a single pass. Users who need custom split logic may use the plain-tier splitters freely — `random_split`, `time_split`, `kfold`, `repeated_kfold`, `holdout_cv`, and `group_kfold` / `group_split` (with `time_series_cv` and `purged_kfold` still to come); the library performs no post-hoc split-imbalance checking, so distributional quality on a user-chosen split is the user's responsibility. In particular, the **Unsplittable Rare Row Routing** guarantee (ADR-0048) is intrinsic to the shuffled profile-stratified path only — no plain, temporal, or grouped splitter routes rare labels into train, so none carries a label-presence guarantee. The profile-stratified entry points are the library's guarantee of a distributionally-representative split — see the **Stratification Signal Viability Contract** below.
  _Avoid_: smart split, missingness-aware split, profile-aware split

### Stratification Signal Taxonomy

The signals used to build the binary label matrix for profile-stratified splitting. Each signal produces one binary column in the matrix (1 = row exhibits this signal, 0 = does not). All derived per-row from the profile and raw DataFrame:

- **Missingness signal** — one label per column with `effective_null_ratio > 0` and without `MissingnessFlag.DropCandidate`. Derived from the DataFrame's null mask. `DropCandidate` columns (>50% missing) are excluded: they are dropped by Phase 2 and consume a label slot while protecting nothing downstream.
- **Joint MAR missingness signal** — one label per pair of `MARSuspect`-correlated columns. A row gets `1` if it is missing in BOTH correlated columns simultaneously, using the effective null mask (string sentinels included) for both columns. Preserves the correlation structure that MICE relies on.
- **Numeric extreme value signal** — one label per numeric column. A row gets `1` if its value is below `p5` or above `p95`. The upper threshold is extended to `p99` when `SkewSeverity.Severe` OR `KurtosisTag.Leptokurtic` — either condition alone is sufficient, because both indicate heavier-than-normal tails where p95 under-captures. Derived from `PercentileSnapshot` and `NumericStats.kurtosis_tag`.
- **Zero/negative value signal** — one label per numeric column where `SkewSeverity >= High` **and** `min <= 0`. A row gets `1` if its value is `<= 0`. The `min <= 0` precondition is mandatory: a column with no zero/negative values would produce an all-zeros flag that carries no information. Distinct from the extreme value signal — in a zero-inflated column (a large point mass at zero) `p5` itself equals zero, so the extreme signal's `value < p5` catches nothing; this signal is the only one covering the zero mass. Derived directly from the DataFrame (not in Phase 1 profile). Protects Phase 4 log-transform from unseen zero/negative values.
- **Rare categorical label signal** — one label **per rare value** (not per column). For each value in `RareCategoryStats.rare_label_values` (row frequency below 5%), a row gets `1` if it equals that value. Per-value granularity is required because the stratification guarantee is per-label presence in both splits ("Phase 5 Encoding has all labels in both splits") — a single per-column density flag balances the *count* of rare rows but does not guarantee any *specific* rare label appears on both sides. Rare values too sparse to satisfy the viability floor cannot be balanced (physics: a value with one row cannot be in two splits); those rows are instead handled by the **Unsplittable Rare Row Routing** rule below. Derived from profile.
- **Boolean minority signal** — one label per boolean column where `min(true_ratio, false_ratio) < 0.05`. A row gets `1` if it holds the minority value. Derived from `BooleanStats`.
- **NearConstant numeric minority signal** — one label per numeric column with `NumericFlag.NearConstant` (mode frequency > 90%). A row gets `1` if its value differs from the column mode. For `NumericKind.BoundedDiscrete` columns, exact equality is used; for `NumericKind.Continuous`, a band of `mode ± 0.5 * IQR` defines "at mode." Protects the structurally-rare non-constant rows that the extreme value signal misses in symmetric near-constant distributions.
- **Bimodal minority-cluster signal** — one label per numeric column with `NumericFlag.Bimodal`. Each row is assigned to its nearest of the two GMM centers (`BimodalStats.center1`, `center2`); a row gets `1` if it falls in the **less-populous** cluster, where "less-populous" is counted on the DataFrame being split rather than read from `minority_weight` (the profile stores no convention tying `minority_weight` to a specific center). Protects Phase 2's **Bimodal Imputation Framework**: cluster-conditional fill and GMM sampling both fit on `train_df`, so a split that starves train of the minority mode misestimates `center1`/`center2` and misassigns test-side minority rows. Mirrors the NearConstant rationale — a minority mode near the column center sits in neither tail and is invisible to the extreme value signal. Emitted at `_PRIORITY_NUMERIC` and subject to the same viability, redundancy, and cap gates.
- **Compound missingness row signal** — one label for the dataset as a whole when `row_missingness_p90 > 0`. A row gets `1` if its count of missing columns exceeds `RowMissingnessDistribution.row_missingness_p90`. Protects "globally sparse" rows — those missing in many columns simultaneously — which the per-column missingness signals do not individually protect. These rows are the hardest inputs for MICE because they must be imputed jointly across all missing columns.
- **Target signal** — labels for the declared target column, built by a two-tier rule that reuses the Phase 1 classification rather than a local heuristic. **Tier 1** — a non-numeric target, or a numeric target classified `NumericKind.BoundedDiscrete` (e.g. a 1–5 rating), emits one label per class. **Tier 2** — any other numeric target is quantile-binned into `min(5, n_unique)` buckets computed on non-null values only, plus a separate "target is missing" label so null-target rows are balanced rather than silently absent from every bucket. The last class/bucket is dropped dummy-style (see the viability contract). The target is **never evictable** by the signal cap; when a target class is too sparse to satisfy the viability floor, its rows are handled by **Unsplittable Rare Row Routing** rather than dropped.

**Datetime columns never contribute a stratification signal.** Stratification balances distributional properties across a *shuffled* partition; it assumes rows are exchangeable. A `Datetime` column that mattered for the split would matter because the task is temporal — and a temporal task requires the *opposite* of stratification: a chronological, no-shuffle partition that keeps future out of train. Whether a dataset is temporal is modeling intent, not a data property (a `signup_date` feature on a cross-sectional churn model is not a forecast), so the library never infers it. Temporal splitting is served by the user-invoked `DataSplitter.time_split`; the profile-stratified path ignores datetime columns entirely and never auto-routes to a time split. See ADR-0049.

### Stratification Signal Viability Contract

Every candidate signal must pass four gates, in order, before it enters the label matrix. The contract exists because stratification operates under a hard budget (unlike Phase 1 profiling, where computing every indicator is free): `iterstrat` can only place a positive of every label into every partition when each label has enough positives, and every extra signal sparsifies the label-combination space. The governing principle is therefore the *fewest signals that capture the most distributional coverage* — the opposite of the accuracy-over-speed principle that governs profiling.

1. **Relevant** — a downstream phase's quality must depend on the property being balanced.
2. **Viable** — `min(positives, negatives) >= floor`, where `floor = k` for k-fold and `ceil(2 / min(test_size, 1 − test_size))` for shuffle-split. The floor is threaded into `build_label_matrix` from the caller (which knows the split intent) as a `min_positives` argument; the matrix builder itself stays ignorant of split modes. This gate subsumes the old all-zeros drop *and* an all-ones drop: an all-zeros signal has zero positives, an all-ones signal has zero negatives, and both fail the two-sided check.
3. **Non-redundant** — two signals that impose the same balancing constraint are collapsed, keeping the higher-priority one. Redundancy is measured by correlation strength (near `+1` identical or near `−1` mirror-image — both impose the same constraint), with a conservative threshold so only near-perfect duplicates are removed. Mutually-exclusive class sets (target classes, quantile buckets) drop their last member dummy-style, which removes the mirror-image double-count of a binary target at the source.
4. **Prioritized** — when still over the cap after gates 1–3, retain by importance: **target (never evictable) → rare categorical → numeric extremes/skew → missingness (last)**. Within a family, the rarer viable signals are kept first (they are the ones a naive random split is most likely to mishandle).

The cap is `min(max_stratification_signals, n_rows / rows_per_signal)` — the row-based term guards against handing the splitter more simultaneous balancing constraints than the dataset can support (the classic more-columns-than-rows failure). `max_stratification_signals` and `rows_per_signal` are configurable. When even the target cannot be supported, the matrix is returned empty and the splitter falls back to a random split.

- **Unsplittable Rare Row Routing** — a target class or rare categorical value with fewer rows than the viability floor cannot appear in both partitions (a single-row label physically cannot be split). Rather than leaving placement to chance, those rows are deterministically routed into the **training** partition, guaranteeing the label is learned at fit time and eliminating unseen-category failures in Phase 5 at transform time. This is a split-side action applied after `iterstrat` decides the rest of the partition; it is performed silently (no runtime warning, consistent with the library's no-post-hoc-imbalance-check stance) and documented as behaviour. The trade-off is evaluation-side only — an ultra-rare label cannot be evaluated on a held-out set regardless — never a model-side or overfitting cost, as the forced rows number a handful at most.

## Grouped Split

A split in which rows sharing a **Group** are kept together — every row of a group lands on the same side of every train/val boundary.

- **Group** — a set of rows that are not independent because they share an entity (same patient, user, session, device). Declared explicitly by the user as a column name (`group_kfold(group_column=...)`, `group_split(group_column=...)`); the library never infers grouping, mirroring its refusal to infer temporality (ADR-0049). Membership in a group is domain knowledge the data cannot reveal.
- **Group Leakage** — the failure a grouped split prevents: the same group appearing in both train and val, letting a model memorise the entity and post an optimistic validation score that collapses on unseen groups. Distinct from the distributional imbalance that Profile-Stratified Split addresses.
- **Group-disjointness** — the invariant that no group straddles a partition boundary. In the smart-tier grouped splitter it is a **hard constraint, never traded away**; target-class balance is layered on top on a **best-effort** basis only (`StratifiedGroupKFold` semantics). Grouped splitting balances the **target only**, not the full stratification signal matrix — jointly satisfying whole-group constraints and the full matrix is over-constrained and frequently has no valid partition. See ADR-0052.
  _Avoid_: entity split, cluster split, blocked split (blocking means something else in time-series)

## Temporal Cross-Validation

Two plain-tier CV schemes for ordered data, never stratified (shuffling is forbidden — see ADR-0049). Both sort by a user-declared `time_column`. They differ in their causality guarantee; both are specified because they serve different modelling assumptions. See ADR-0053.

**Status: designed, not implemented.** `DataSplitter` currently ships `random_split`, `time_split`, `kfold`, `repeated_kfold`, `holdout_cv`, `group_split`, `group_kfold`, `profile_stratified_split`, and `profile_stratified_kfold`. Neither `time_series_cv` nor `purged_kfold` exists yet, so `label_end_column`, **Purge**, and **Embargo** are vocabulary for a future scope rather than current behaviour.

- **Walk-Forward CV** — forward-chaining folds where **train is always before val** (`time_series_cv`). Geometry is `window="expanding"` (train grows from the start) or `window="rolling"` (fixed-width train window slides forward). Strict causality: the past never sees the future. A `gap` (in rows) drops the boundary rows between train-end and val-start to protect a forward-looking label horizon. Each fold uses less data than purged K-fold, and early folds are small.
  _Avoid_: rolling-origin (name the geometry, not the method)
- **Purged K-Fold** — the timeline is cut into `n_splits` contiguous blocks; each block is val in turn, and **train is every other block, both before and after** val (`purged_kfold`). Uses future data to predict past — acceptable when the only concern is label-overlap leakage, not causal ordering — in exchange for equal-sized folds each using ~(K−1)/K of the data.
- **Purge** — dropping training rows whose **Label Window** overlaps the val block's time span. Enabled by an opt-in `label_end_column` the user declares (the time each row's label is realised — modelling knowledge the library never infers, mirroring `time_column` and `group_column`). When absent, purging degrades to the embargo window only.
- **Embargo** — dropping training rows in a window *immediately after* the val block, where serial correlation would otherwise bleed val information back into train. Specified as a **time duration** in the units of `time_column` (not a row count or fraction — those misbehave under irregular sampling). Relevant only to purged K-fold, which alone has train-after-val.

## Profile Serialization

- **Compact Profile Report** — The human-readable serialization of `StructuralProfileResult`, produced by `to_markdown()`. Covers every information category but depth-limits list-heavy fields: `top_values` capped at 3 entries; correlation matrices replaced by top-5 highest absolute Pearson and top-5 highest absolute Spearman per column; histogram bins, `missingness_matrix`, `memory_breakdown`, and `total_rows` (per-column) dropped. All scalar fields are kept in full. Renders using two-tier column rendering. See ADR-0040.
  _Avoid_: profile summary, readable profile, human profile

- **Full Profile Report** — The lossless Markdown serialization of `StructuralProfileResult`, produced by `to_full_markdown()`. Equivalent in content to `to_dict()` / `to_json()`. Intended for debugging and archival, not routine human inspection. See ADR-0040.
  _Avoid_: full markdown, complete profile

- **Two-Tier Column Rendering** — The rendering strategy used by the Compact Profile Report. All columns appear in the Column Summary table. Columns meeting the **clean threshold** (no `MissingnessFlag`, no `NumericFlag`, `MissingSeverity` is `None` or `Minor`, `NonlinearityTag` is `None` or `Linear`) appear in the summary table only. All other columns receive a full detail section in the Flagged Columns block, ordered by descending severity then alphabetically. See ADR-0040.
  _Avoid_: tiered rendering, anomaly-first rendering

## Persistence

Three free functions — `serialize(obj) -> bytes`, `deserialize(bytes) -> obj`, `inspect(bytes) -> dict` — and nothing else. They handle the three objects that cross the boundary: the pure `StructuralProfileResult`, the value-free `ImputationDecision`, and each `FittedUnit`. The library hands back bytes and takes bytes; **where those bytes live is entirely the user's**, so there is no store abstraction, no key scheme, and no cache. See ADR-0072.

- **Bare bytes, no store** — the `Store Port` (`put_document`/`get_document`/`put_blob`/`get_blob`/`exists`), its `LocalFileStore` default, content-addressed `Artifact Identity` keying, the `Data Fingerprint` that keyed it, `Manifest-Last Commit`, and `ArtifactIdentityMismatchError` were all designed for a resumable executor that no longer exists. With execution stateless and user-orchestrated (ADR-0071), the machinery had no consumer: a user who owns the loop already knows which units they trained and where they put them. A filesystem is not a thing the library needs to abstract over on their behalf. What survives of the identity concern is the honest minimum — provenance is *stamped and checkable*, never used to silently accept or reject a cache hit the library never makes.
- **Self-describing envelope** — every artifact is a JSON header (`kind`, `format_schema_version`, `library_version`, and for a unit its `produced_with` dependency stamp) plus, for a fitted unit only, an opaque joblib payload holding the learned state. A decision's hyperparameter-override delta rides inside its envelope, so a round-tripped plan re-stamps the same merged units.
- **`inspect` reads the header without reconstructing** — the cheap "what is this and can I load it" question, answerable on bytes from an unknown source without unpickling anything.
- **Reconstruction is strict, one axis is lenient** — `deserialize` raises `IncompatibleArtifactError` when the installed sklearn/numpy/joblib cannot safely rebuild the payload (ADR-0063). A differing *Python* version is the single lenient branch: it warns via `ArtifactPythonVersionWarning` and proceeds. Recovery from an incompatible artifact is always **retrain**, never partial reconstruction — see ADR-0065.
  _Avoid_: store, artifact store, cache, repository, save/load

## Observability

Long-running orchestrator calls surface what they are doing so a user watching a multi-minute run knows it is progressing, not hung — and so the run leaves a diagnostic trail. Two concerns, one backbone: every meaningful moment emits a single **Pipeline Event**; that same Event feeds both progress reporting and diagnostic tracing.

**Scope is the orchestrators, and Phase 2 fitting is no longer one of them.** `StructuralProfiler.profile` (including the expensive correlation/nonlinearity stages) and `EvaluationOrchestrator` emit Events; `decide` and `fit_unit` emit none and take no `observer=`. That is not a gap left by the executor's removal but the consequence of user-orchestrated execution: a caller driving units by hand already knows which unit is running and when, so the position-in-a-call that an Event stream exists to report is information they own. What they cannot see from outside is how an individual fit went, and that comes back structurally as **FitSignals** on the `UnitFitResult` (ADR-0074).

- **Pipeline Event** — A structured record emitted by the library at each meaningful moment of an orchestrator call. The single atomic unit of observability; both progress and trace consume the same Events. Carries `phase`, `stage`, `column`, `index`, `total`, a ready-made human `message`, and an `event_type` — one of `stage_start`, `stage_end`, `item` (per-column heartbeat, e.g. column 7/12), `substep` (a Substep heartbeat *below* the column, e.g. "MICE block fitting", "diagnostics fold 3/5"), `decision` (a routing/strategy choice and its reason), or `warning` (a recoverable soft fallback). Emitted at three tiers: phase and stage boundaries always, item-level per column inside the expensive iterative stages, and Substep-level for the sub-column work inside a column/block fit. A watching consumer drives a coarse progress bar off `item` and a live detail line off `substep`, so no stretch of work is silent (superseding ADR-0054's earlier "column-level is the item floor"; see ADR-0055).
  _Avoid_: log line, message, LogRecord (the raw string is a rendering of an Event, not the Event)

- **Two-Sink Rule** — Every Pipeline Event goes to both sinks, always: (1) it is written to the `dataforge_ml` stdlib logger at a level derived from `event_type` (`stage_start`/`stage_end`/`item` → DEBUG, `decision` → INFO, `warning` → WARNING) — this is Trace; (2) it is passed to the user's Progress Observer if one was supplied — this is Progress. The two sinks see the identical Event stream and each filters the subset it cares about; there is no second, parallel plumbing.

- **Warning Event** — A Pipeline Event reporting a *recoverable* soft fallback the library took silently (e.g. a profiling coercion that dropped values). Distinct from an exception: hard failures still raise. Warning Events exist so silent recovery decisions leave a visible trail rather than surprising the user downstream. Phase 2's fit-time equivalent is **not** a Warning Event — a fit that cannot proceed raises `UnitNotTrainableError` (there is no soft fallback left to report), and a fit that succeeded with a caveat records it in `FitSignals.warnings` and raises an `ImputationFitWarning`.

- **Progress Reporting** — The live "where am I now" concern: telling a watching user that the run is advancing (e.g. "column 7 of 12"). Distinct from Trace. The library never writes to any stream on its own to satisfy this; it hands Events to a user-supplied **Progress Observer**.
  _Avoid_: verbose mode, status updates

- **Trace** — The after-the-fact diagnostic concern: a durable record of *what happened and why* (routing decisions, chosen strategies), for debugging and audit. Realised by formatting Events onto the named `dataforge_ml` stdlib logger (silent by default via `NullHandler`; the user attaches handlers).
  _Avoid_: debug logs, logging (name the concern, not the mechanism)

- **Progress Observer** — A user-supplied consumer that receives Pipeline Events; the library calls it rather than printing. Supplied per orchestrator as a live `observer=` constructor argument — deliberately *not* a field on `PipelineConfig`, because a live callable would break that config's serializable, setter-only, declarative contract (ADR-0044). There are no library-side on/off knobs for observability: the library always emits every Event, and the observer filters by `event_type` in its own code. The library ships a ready-made default observer that writes human sentences to **stderr** (never stdout, which is reserved for the user's data), for users who just want messages on screen; any other destination (file, notebook, web UI) is a custom observer.
  _Avoid_: callback, hook, listener

- **Per-Call Scoping** — Progress is scoped within a single orchestrator call (`profile()`, `inspect()`, `score_accuracy()`); there is no cross-call run object, so overall "% of the entire pipeline" is deliberately not expressible. The honest unit is position within one call.
  _Avoid_: run progress, global progress, pipeline progress bar

- **Substep** — A unit of progress *below* the column: a named chunk of the sub-column or per-block work that a column/block fit performs (a strategy-block fit, a diagnostics fold, a per-column model fit within a set). Surfaced as a `substep`-type Pipeline Event so a watching user sees continuous motion during the long inner stretches (MICE fitting, cross-validated diagnostics) that were previously silent. Substep is the honest floor — finer than a column, but deliberately *not* solver-iteration granularity (no "MICE round N"), because the library owns every Substep emit point whereas solver rounds would require reaching into an estimator's internals. See ADR-0055.
  _Avoid_: subtask, micro-step, iteration (a Substep is not one solver round)

- **Emitter** — The object an orchestrator threads into its sub-processors so that deep methods can emit Pipeline Events. It carries the `phase` and the Progress Observer, owns the Substep/index bookkeeping, and applies the Two-Sink Rule in one place, so a call site just says what happened (`emitter.substep("MICE block fitting")`). The Emitter is *the* mechanism by which a phase honors the granularity contract: every orchestrator builds one and hands it down explicitly (never an ambient global), which is what lets the pattern hold uniformly across current and future phases. See ADR-0055.
  _Avoid_: reporter, notifier, logger, ambient observer
